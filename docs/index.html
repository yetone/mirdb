MirDB

Persistent Key-Value Store with Memcached Compatibility

A high-performance, LSM tree-based key-value store written in Rust. Drop-in memcached protocol support with disk persistence and crash recovery.

Why MirDB?

Persistence

LSM tree-based storage with Write-Ahead Logging ensures your data survives crashes and restarts.

Compatibility

Drop-in memcached protocol support. Use your existing memcached clients without any code changes.

Performance

Rust-powered async I/O with Tokio delivers blazing fast read and write operations.

Core Features

Everything you need for a reliable, high-performance key-value store

GET/SET/DELETE Operations

Full support for standard key-value operations with TTL (Time-To-Live) support. Set expiration times on your data for automatic cleanup.

Background Compaction

Automatic minor and major compaction processes run in the background, optimizing storage efficiency without impacting performance.

Write-Ahead Logging

WAL ensures crash recovery by persisting all write operations before applying them. Your data is safe even during unexpected shutdowns.

TOML Configuration

Simple, human-readable configuration via TOML files. Easily customize ports, storage paths, memory limits, and more.

Multiple Storage Levels

7-level LSM tree architecture with optimized merging strategies. Data flows efficiently from memory to disk with automatic level management.

Async I/O with Tokio

Built on Tokio for non-blocking async I/O operations. Handle thousands of concurrent connections with minimal resource usage.

How It Works

  1. Write Path: Data is first written to the Write-Ahead Log (WAL), then to the in-memory Memtable.
  2. Flush: When Memtable reaches 4MB, it becomes immutable and is flushed to disk as an SSTable.
  3. Compaction: Background compaction merges SSTables across levels, optimizing read performance and reclaiming space.
  4. Read Path: Reads check Memtable first, then search SSTables from newest to oldest.

Getting Started

Get up and running in minutes

1. Clone and Build

git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

2. Configure (Optional)

Create a config.toml file:

addr = "0.0.0.0:12333"
max_level = 7
work_dir = "/tmp/mirdb"
sst_max_size = "100M"
mem_table_max_size = "4M"

3. Run the Server

./target/release/mirdb-server

4. Connect with Memcached Client

Use any memcached client to connect:

# Using telnet
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get the value
get mykey
VALUE mykey 0 5
hello
END

# Delete the value
delete mykey
DELETED
