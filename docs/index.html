MirDB

A Persistent Key-Value Store with Memcached protocol

Get Started View on GitHub
version 0.1.0

Key Features

🔌

Memcached Protocol

Full compatibility with the Memcached text protocol. Use familiar commands like SET, GET, DELETE with existing Memcached clients.

🌲

LSM-tree Storage

Log-Structured Merge-tree architecture optimized for high write throughput and efficient storage utilization.

📋

Skip-list Memtable

In-memory skip-list data structure for fast reads and writes with O(log n) complexity.

📝

WAL Durability

Write-Ahead Log ensures crash recovery and data durability. Never lose committed data.

📦

SSTable Storage

Sorted String Tables provide efficient on-disk storage with fast sequential reads and bloom filters.

🔄

Compaction

Automatic minor and major compaction processes to merge SSTables, reclaim space, and optimize read performance.

⏰

TTL Support

Time-to-live expiration for keys. Set automatic expiration times for cached data.

Getting Started

Connect to MirDB using the Memcached protocol. Here's a quick example using telnet:

Connect to MirDB

telnet localhost 11211

Store a Value (SET Command)

Use the SET command to store a key-value pair. The syntax is: set <key> <flags> <exptime> <bytes>

set mykey 0 3600 5
hello
STORED

Retrieve a Value (GET Command)

Use the GET command to retrieve stored values:

get mykey
VALUE mykey 0 5
hello
END

Complete Session Example

Here's a complete session demonstrating connection, set, and get operations:

$ telnet localhost 11211
Trying 127.0.0.1...
Connected to localhost.
Escape character is '^]'.

set mykey 0 3600 5
hello
STORED

get mykey
VALUE mykey 0 5
hello
END

Installation

Choose your preferred installation method to get MirDB up and running.

Install with Cargo

Install MirDB using Rust's package manager. Requires Rust and Cargo installed on your system.

Install from crates.io

cargo install mirdb-server

Build from Source

Clone the repository and build from source for the latest development version:

git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

Run the Server

After building, start the MirDB server:

./target/release/mirdb-server

Install with Docker

Run MirDB in a container for easy deployment and isolation.

Pull the Docker Image

docker pull yetone/mirdb:latest

Run the Container

Start a MirDB container with port mapping and persistent storage:

docker run -d \
  --name mirdb \
  -p 11211:11211 \
  -v mirdb-data:/data \
  yetone/mirdb:latest

Docker Compose

Use Docker Compose for more complex setups:

version: '3.8'
services:
  mirdb:
    image: yetone/mirdb:latest
    ports:
      - "11211:11211"
    volumes:
      - mirdb-data:/data
volumes:
  mirdb-data:

Configuration

Configure MirDB using a TOML configuration file or command-line options.

Configuration File

MirDB uses TOML configuration files. Specify the config file path using the -c flag:

Example Configuration (mirdb.toml)

# Network configuration
addr = "0.0.0.0:12333"

# Storage configuration
work_dir = "/var/lib/mirdb"
max_level = 7

# Memory table settings
mem_table_max_size = "4M"
mem_table_max_height = 32
imm_mem_table_max_count = 16

# SSTable settings
sst_max_size = "100M"
block_size = "4K"
block_restart_interval = 16

# Compaction settings
l0_compaction_trigger = 4
thread_sleep_ms = 500

Configuration Options

Parameter Description Default
addr Server listen address and port 0.0.0.0:12333
work_dir Data directory for persistent storage /tmp/mirdb
max_level Maximum LSM tree levels 7
mem_table_max_size Maximum memtable size before flush 4M
sst_max_size Maximum SSTable file size 100M
l0_compaction_trigger Level 0 files count to trigger compaction 4

CLI Options

MirDB supports the following command-line options:

Command Line Usage

# Start with a configuration file
mirdb-server -c /path/to/mirdb.toml

# Start with default configuration
mirdb-server

# Common options
  -c, --config <FILE>    Path to configuration file
  -h, --help             Display help information
  -V, --version          Display version information

Available Flags

-c, --config <FILE>
Specify the path to a TOML configuration file. If not provided, MirDB will use default settings.
-h, --help
Display help information and available command-line options.
-V, --version
Display the MirDB version number.

Size Units

Configuration values support the following size suffixes:

  • K - Kilobytes (1,024 bytes)
  • M - Megabytes (1,048,576 bytes)
  • G - Gigabytes (1,073,741,824 bytes)
  • T - Terabytes (1,099,511,627,776 bytes)
