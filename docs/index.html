MirDB

A Persistent Key-Value Store with Memcached Protocol

Get Started View on GitHub

Key Features

Memcached Protocol

Full compatibility with the Memcached text protocol. Use your existing memcached clients and tools without any code changes.

Persistence

Durable storage with write-ahead logging ensures your data survives restarts. Unlike memcached, your data is safely persisted to disk.

LSM Tree Storage

Log-Structured Merge tree architecture optimized for write-intensive workloads. Efficient storage with automatic level management across 7 levels.

Skip List Memtable

In-memory skip list data structure provides O(log n) operations. Fast reads and writes with efficient memory utilization for the active working set.

Automatic Compaction

Background compaction automatically merges and optimizes SSTables. Both minor (memtable flush) and major compaction maintain storage efficiency.

Architecture

MirDB implements an LSM (Log-Structured Merge) tree storage engine designed for high write throughput with efficient reads.

Write-Ahead Log (WAL)

The WAL provides durability by persisting writes before acknowledging them. Each write is first appended to the WAL, ensuring data can be recovered after crashes. WAL segments are Snappy-compressed and aligned for efficient storage.

Memtable

The memtable is an in-memory skip list data structure that accepts all incoming writes. It provides O(log n) insert and lookup operations. When the memtable reaches 4MB, it becomes immutable and a new memtable is created.

SSTable (Sorted String Table)

SSTables are immutable on-disk files storing key-value pairs sorted by key. Each SSTable contains data blocks with prefix compression, a meta block with min/max keys and Cuckoo filter, an index block for efficient lookups, and a footer with checksums.

Compaction

MirDB runs two types of compaction in background threads:

  • Minor Compaction: Flushes immutable memtables to Level 0 SSTables
  • Major Compaction: Merges SSTables between levels, removing duplicates and deleted keys

The LSM tree supports up to 7 levels, with each level 10x larger than the previous.

Quick Start

Get up and running in minutes.

1. Build from Source

Clone the repository and build with Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build the release binary
cargo build --release

2. Start the Server

Run MirDB with the default configuration. The server listens on 0.0.0.0:12333 by default:

# Start the server
./target/release/mirdb-server -c etc/mirdb.toml

3. Connect and Use

Connect using any memcached client or telnet on port 12333:

# Connect to MirDB
telnet localhost 12333

# SET a key-value pair
# Format: set <key> <flags> <ttl> <bytes>
set mykey 0 0 5
hello
STORED

# GET the value
get mykey
VALUE mykey 0 5
hello
END

MirDB is fully compatible with the memcached text protocol. Use your existing memcached client libraries without any code changes.

Supported Commands

MirDB implements the Memcached text protocol, enabling compatibility with existing clients and tools.

Storage Commands

SET

Store a key-value pair with optional expiration time.

set <key> <flags> <exptime> <bytes> [noreply]\r\n
<data>\r\n

Example:

set mykey 0 3600 5
hello
STORED

ADD

Store a key-value pair only if the key does not already exist.

add <key> <flags> <exptime> <bytes> [noreply]\r\n
<data>\r\n

REPLACE

Store a key-value pair only if the key already exists.

replace <key> <flags> <exptime> <bytes> [noreply]\r\n
<data>\r\n

APPEND

Append data to the end of an existing value.

append <key> <flags> <exptime> <bytes> [noreply]\r\n
<data>\r\n

PREPEND

Prepend data to the beginning of an existing value.

prepend <key> <flags> <exptime> <bytes> [noreply]\r\n
<data>\r\n

Retrieval Commands

GET

Retrieve one or more keys from the store.

get <key> [<key2> ...]

Example:

get mykey
VALUE mykey 0 5
hello
END

GETS

Retrieve keys with CAS (Check-And-Set) token.

gets <key> [<key2> ...]

Deletion Commands

DELETE

Remove a key from the store.

delete <key> [noreply]

Example:

delete mykey
DELETED

MirDB-Specific Commands

INFO

Display database status and level information.

info

MAJOR_COMPACTION

Trigger manual compaction of SSTables.

major_compaction

Response Codes

STORED - Data stored successfully
NOT_STORED - Data not stored (condition not met)
EXISTS - CAS check failed
NOT_FOUND - Key not found
DELETED - Key deleted successfully
ERROR - Unknown command

Performance

Configuration and performance characteristics.

Default Configuration

Parameter Default Value Description
addr 0.0.0.0:12333 Listen address and port for memcached protocol connections
max_level 7 Maximum LSM tree levels (each level 10x larger than previous)
sst_max_size 100MB Maximum SSTable file size before splitting
mem_table_max_size 4MB Maximum memtable size before flush to disk
block_size 4KB Data block size for SSTable storage
work_dir /tmp/mirdb Default data directory path

Performance Characteristics

Write-Through Durability

All writes are immediately persisted to the Write-Ahead Log (WAL) before acknowledgment. This ensures data durability even in the event of crashes, while maintaining high write throughput through sequential I/O.

Lazy Expiration

Expired keys are cleaned up lazily during read operations and compaction. This approach reduces write amplification and maintains consistent performance without dedicated expiration threads.

Background Compaction

Compaction runs in background threads, minimizing impact on read/write latency. Level-based compaction ensures efficient space utilization across 7 LSM levels.

Memory Efficiency

The skip list memtable provides O(log n) operations with a configurable 4MB default size. Immutable memtables are queued for efficient batch flushing to SSTables.
