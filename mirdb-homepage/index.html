MirDB

A persistent key-value store with Memcached protocol compatibility, written in Rust

Disk Persistence Memcached Protocol Written in Rust
View on GitHub Get Started

Key Features

Memcached Protocol

Full compatibility with the Memcached text protocol. Supports essential commands including SET, GET, and DELETE operations, allowing seamless integration with existing Memcached clients and tools.

Disk Persistence

Unlike pure Memcached, MirDB persists data to disk ensuring durability. Your data survives server restarts and crashes, combining the speed of in-memory caching with the reliability of persistent storage.

LSM Tree Architecture

Built on a Log-Structured Merge tree design with WAL (Write-Ahead Log) for crash recovery, an in-memory Memtable for fast writes, and SSTables for efficient disk storage and retrieval.

Built with Rust

Written in Rust for memory safety and high performance. Powered by Tokio for async I/O, delivering excellent throughput while preventing common memory-related bugs and data races.

Getting Started

Get MirDB up and running in minutes. Follow these steps to clone, build, and start using MirDB locally.

1. Clone the Repository

First, clone the MirDB repository from GitHub:

git clone https://github.com/mirdb/mirdb.git
cd mirdb

2. Build the Project

Build MirDB using Cargo (Rust's package manager):

cargo build --release

3. Start the Server

Run MirDB to start the server on the default port (12333):

cargo run --release

You can also run the binary directly: ./target/release/mirdb

4. Basic Operations

Once the server is running, you can interact with it using netcat or any Memcached client. Here are examples using netcat:

SET Operation - Store a Value

Store a key-value pair in MirDB:

# Connect to MirDB and store a value
echo -e "set mykey 0 0 5\r\nhello\r" | nc localhost 12333

# Expected response: STORED

GET Operation - Retrieve a Value

Retrieve the stored value from MirDB:

# Connect to MirDB and retrieve the value
echo -e "get mykey\r" | nc localhost 12333

# Expected response:
# VALUE mykey 0 5
# hello
# END

Architecture

MirDB uses a Log-Structured Merge (LSM) tree architecture optimized for write-heavy workloads while maintaining efficient reads.

📝 Write-Ahead Log (WAL)

The WAL ensures durability by persisting every write operation to disk before acknowledging it. In case of a crash, MirDB can recover all committed writes by replaying the WAL. Records are Snappy-compressed and aligned for efficient I/O.

🧠 Memtable

The Memtable provides fast in-memory storage using a skip list data structure. Writes are first applied to the active memtable for low-latency operations. When the memtable reaches its size limit (default 4MB), it becomes immutable and is scheduled for flushing to disk.

💾 SSTables (Sorted String Tables)

SSTables provide persistent, sorted storage organized across multiple levels. Level 0 contains recently flushed data that may overlap. Higher levels (1 to N) are sorted and non-overlapping within each level. Background compaction merges and organizes data for efficient reads.
