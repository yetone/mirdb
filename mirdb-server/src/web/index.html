What is MirDB?

MirDB is a high-performance, persistent key-value store that speaks the Memcached protocol. Built entirely in Rust, it combines the familiarity of Memcached's text protocol with the durability of an LSM-Tree storage engine.

Drop-in Compatible

Use your existing Memcached clients and libraries. MirDB supports the standard text protocol including SET, GET, DELETE, and more.

Persistent Storage

Unlike in-memory caches, MirDB persists your data to disk using an LSM-Tree architecture. Your data survives restarts.

High Performance

Built with Rust and Tokio for async I/O, MirDB delivers low-latency reads and high-throughput writes.

Simple Deployment

Single binary, zero external dependencies. Configure via TOML and run anywhere Rust compiles.

Quick Start

1. Install MirDB

cargo install mirdb

2. Start the Server

mirdb --config mirdb.toml

3. Store a Value

echo -e "set mykey 0 0 5\r\nhello\r" | nc localhost 12333

4. Retrieve the Value

echo -e "get mykey\r" | nc localhost 12333

Supported Commands

MirDB implements the Memcached text protocol. The following commands are fully supported:

SET

Store a key-value pair with optional expiration time and flags.

set <key> <flags> <exptime> <bytes>\r\n<data>\r\n

GET

Retrieve one or more values by their keys.

get <key>*\r\n

ADD

Store a value only if the key does not already exist.

add <key> <flags> <exptime> <bytes>\r\n<data>\r\n

REPLACE

Store a value only if the key already exists.

replace <key> <flags> <exptime> <bytes>\r\n<data>\r\n

DELETE

Remove a key-value pair from the store.

delete <key>\r\n

APPEND

Append data to an existing key's value.

append <key> <flags> <exptime> <bytes>\r\n<data>\r\n

PREPEND

Prepend data to an existing key's value.

prepend <key> <flags> <exptime> <bytes>\r\n<data>\r\n

Architecture

MirDB uses a Log-Structured Merge Tree (LSM-Tree) storage engine, providing excellent write performance and data durability.

Write-Ahead Log (WAL)

Every write is first appended to the WAL on disk, ensuring durability. In case of a crash, the WAL is replayed to recover uncommitted data.

MemTable (SkipList)

Writes are buffered in an in-memory SkipList data structure, providing O(log n) insertions and lookups. When the MemTable reaches a threshold size, it's flushed to disk.

SSTable (Sorted String Table)

Immutable, sorted files on disk. SSTables are organized in levels and periodically compacted to reclaim space and optimize reads.

LSM-Tree Benefits

The LSM-Tree architecture optimizes for write-heavy workloads by batching writes and performing sequential I/O. Compaction runs in the background to maintain read performance.
