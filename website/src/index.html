MirDB

A Persistent Key-Value Store with Memcached Protocol

Built on LSM tree architecture with Tokio async runtime. Use your existing memcached clients with disk persistence.

Get Started View on GitHub

Features

Powerful capabilities that set MirDB apart from traditional caching solutions

Disk Persistence

Unlike memcached, MirDB persists data to disk using SSTables. Your data survives server restarts and system failures.

LSM Tree Architecture

Built on a Log-Structured Merge-tree design with memtables, immutable memtables, and multi-level SSTable compaction for efficient writes.

Memcached Protocol

Full compatibility with the standard memcached text protocol. Use your existing memcached clients without any code changes.

Snappy Compression

Data blocks are compressed using Snappy for reduced storage footprint while maintaining fast read and write performance.

Bloom Filters

SSTable-level bloom filters reduce unnecessary disk reads by quickly determining if a key exists in a given file.

Tokio Async Runtime

Powered by Tokio for high-performance asynchronous I/O, enabling efficient handling of many concurrent connections.

Quick Start

Get up and running with MirDB in minutes

1 Install MirDB

Install MirDB using Cargo or download the pre-built binary.

bash 
# Install with Cargo
cargo install mirdb

# Or download pre-built binary
curl -L https://github.com/akiozihao/mirdb/releases/latest/download/mirdb -o mirdb
chmod +x mirdb

2 Start the Server

Run MirDB with your preferred configuration options.

bash 
# Start with default settings (port 11211, data in ./mirdb-data)
mirdb

# Or configure port and data directory
mirdb --port 11211 --data-dir /var/lib/mirdb

3 Connect and Use

Use any memcached client to interact with MirDB using standard commands.

terminal 
# Connect using telnet or nc
telnet localhost 11211

# SET a key-value pair (flags=0, exptime=0, bytes=5)
SET mykey 0 0 5
hello
STORED

# GET the value
GET mykey
VALUE mykey 0 5
hello
END

# DELETE a key
DELETE mykey
DELETED

Architecture

MirDB uses an LSM tree (Log-Structured Merge Tree) architecture for efficient writes and reads.

graph TD A[Write Request] --> B[WAL] B --> C[Memtable] C --> D{Memtable Full?} D -->|Yes| E[Immutable Memtable] D -->|No| C E --> F[Flush to Disk] F --> G[SSTable L0] G --> H{Compaction Needed?} H -->|Yes| I[Merge SSTables] I --> J[SSTable L1+] H -->|No| G K[Read Request] --> L{In Memtable?} L -->|Yes| M[Return from Memory] L -->|No| N{In Immutable?} N -->|Yes| M N -->|No| O[Search SSTables] O --> P[Use Bloom Filters] P --> Q[Return Data]

Write-Ahead Log (WAL)

Every write is first recorded to the WAL for durability. This ensures data isn't lost even if the server crashes before flushing to disk.

Memtable

An in-memory sorted data structure (skip list) that holds recent writes. Provides fast reads and writes before data is persisted.

Immutable Memtable

When the memtable reaches capacity, it becomes immutable and a new memtable is created. The immutable memtable is then flushed to disk as an SSTable.

Sorted String Tables (SSTables)

Immutable, sorted files on disk. Organized in levels (L0, L1, ...) with periodic compaction to merge and optimize storage.

Protocol Reference

MirDB implements the memcached text protocol, allowing you to use existing memcached clients. Additionally, MirDB provides custom commands for database management.

Standard Memcached Commands

Command Syntax Description
SET SET <key> <flags> <exptime> <bytes> Store data under the specified key
GET GET <key> Retrieve data for the specified key
DELETE DELETE <key> Delete the specified key from the store
ADD ADD <key> <flags> <exptime> <bytes> Store data only if the key does not exist
REPLACE REPLACE <key> <flags> <exptime> <bytes> Store data only if the key already exists
FLUSH_ALL FLUSH_ALL [delay] Invalidate all existing items

MirDB-Specific Commands

These commands are unique to MirDB and not part of the standard memcached protocol.

Command Syntax Description
INFOMirDB INFO Get server statistics and database information
MAJOR_COMPACTIONMirDB MAJOR_COMPACTION Trigger manual compaction of SSTable files
