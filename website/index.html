MirDB

Persistent Key-Value Store with Memcached Protocol

A drop-in replacement for memcached with built-in persistence. Written in Rust for safety and performance.

Get Started View on GitHub

Key Features

🔌

Memcached Protocol Compatibility

Full compatibility with the standard memcached text protocol. Use your existing memcached clients without any modifications - just point them to MirDB.

💾

Persistent Storage

Unlike memcached, MirDB persists all data to disk using SSTables (Sorted String Tables). Your data survives server restarts and crashes.

🌲

LSM Tree Architecture

Built on an LSM (Log-Structured Merge-tree) design with memtables, immutable memtables, and multi-level SSTable compaction for optimal write performance.

⚡

Async Networking

Powered by Tokio async runtime for high-performance, non-blocking I/O. Handle thousands of concurrent connections efficiently.

📝

Write-Ahead Logging

Every write is first recorded in the Write-Ahead Log (WAL) before being applied. Ensures durability and enables crash recovery.

🔄

Configurable Compaction

Automatic background compaction with configurable strategies. Minor compaction flushes memtables, major compaction optimizes SSTable levels.

Quick Start

1. Clone and Build

git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

2. Configure (Optional)

# mirdb.toml
[server]
listen_addr = "0.0.0.0:12333"
work_dir = "/tmp/mirdb"

[storage]
max_lsm_levels = 7
mem_table_max_size = 4194304
sstable_max_size = 104857600

3. Run the Server

./target/release/mirdb-server

4. Connect with any Memcached Client

# Using telnet
telnet localhost 12333
set mykey 0 0 5
hello
STORED
get mykey
VALUE mykey 0 5
hello
END

Supported Commands

Storage Commands

Command Description
SETStore a key-value pair
ADDStore only if key doesn't exist
REPLACEStore only if key exists
APPENDAppend data to existing value
PREPENDPrepend data to existing value

Retrieval Commands

Command Description
GETRetrieve value by key
GETSRetrieve value with CAS token
DELETERemove a key-value pair

MirDB-Specific Commands

Command Description
INFODisplay server statistics
MAJOR_COMPACTIONTrigger manual major compaction

Configuration

Parameter Default Description
listen_addr 0.0.0.0:12333 Server listen address and port
work_dir /tmp/mirdb Directory for data storage
max_lsm_levels 7 Maximum LSM tree levels
mem_table_max_size 4MB Memtable size before flush
sstable_max_size 100MB Maximum SSTable file size
block_size 4KB SSTable block size
