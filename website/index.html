MirDB

Persistent Key-Value Store with Memcached Compatibility

A drop-in replacement for memcached that persists your data to disk. Built with Rust for performance and reliability, using an LSM-tree architecture for efficient writes and reads.

Why MirDB?

The best of memcached with the reliability of persistent storage

Standard Memcached

  • ✗ Data lost on restart or crash
  • ✗ In-memory only storage
  • ✓ Fast read/write operations
  • ✓ Simple key-value interface

MirDB

  • ✓ Data survives restarts and crashes
  • ✓ Durable disk-based storage with SSTables
  • ✓ Fast read/write via LSM-tree architecture
  • ✓ Same memcached protocol - drop-in replacement

Unlike memcached, MirDB persists your data to disk. Use your existing memcached clients without any code changes while gaining the reliability of durable storage. Your data survives restarts, crashes, and power failures.

Key Features

Everything you need for a reliable, persistent key-value store

Memcached Protocol Compatibility

Use your existing memcached clients without any code changes. MirDB implements the standard memcached text protocol, making it a true drop-in replacement for your caching layer.

Persistent Storage

Unlike memcached, your data survives restarts. MirDB stores data in SSTables (Sorted String Tables) on disk, ensuring durability without sacrificing the speed you expect.

LSM-Tree Architecture

Built on a Log-Structured Merge-tree design for write-optimized performance. Data flows through memtables to sorted SSTables across multiple levels, balancing write speed with read efficiency.

Async Networking (Tokio)

Powered by Tokio, Rust's leading async runtime. Handle thousands of concurrent connections efficiently with non-blocking I/O and minimal resource consumption.

Background Compaction

Automatic background threads handle both minor and major compaction. Your data stays organized and queries remain fast without any manual intervention or downtime.

Write-Ahead Logging

Every write is logged before being applied, ensuring crash recovery and data integrity. Even in unexpected shutdowns, your data remains safe and recoverable.

Quick Start

Get MirDB running in minutes

1. Install

git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

2. Run

./target/release/mirdb-server

3. Connect

# Using telnet or any memcached client
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get it back
get mykey
VALUE mykey 0 5
hello
END

How It Works

LSM-Tree data flow from write to disk

Understanding LSM-Tree Architecture

MirDB uses a Log-Structured Merge-tree (LSM-tree) architecture, which is optimized for write-heavy workloads. This design provides several key benefits:

  • Efficient Write Performance: All writes go sequentially to the WAL and memtable, avoiding random disk I/O. This makes writes extremely fast compared to traditional B-tree databases.
  • Durability via WAL: The Write-Ahead Log ensures that every write is persisted before acknowledgment, providing crash recovery and data safety.
  • Background Compaction: Data is organized through compaction processes that run in the background. Minor compaction flushes memtables to Level 0 SSTables, while major compaction merges SSTables across levels to maintain read performance and reclaim space.
  • Tiered Storage Levels: SSTables are organized into levels (0 through 7 by default). Lower levels may have overlapping key ranges, while higher levels are fully sorted and non-overlapping, enabling efficient binary search during reads.

Supported Commands

Standard memcached commands plus MirDB extras

Command Description
SET Store a key-value pair
GET Retrieve value by key
GETS Retrieve value with CAS token
ADD Store only if key doesn't exist
REPLACE Store only if key exists
APPEND Append data to existing value
PREPEND Prepend data to existing value
DELETE Remove a key-value pair
INFO Get server statistics (MirDB)
MAJOR_COMPACTION Trigger manual compaction (MirDB)

Command Examples

SET Command

Store a key-value pair with optional flags and TTL.

Request: 
set <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n
Example: 
set mykey 0 0 5
hello
Response: 
STORED

GET Command

Retrieve one or more values by key.

Request: 
get <key1> [<key2> ...]\r\n
Example: 
get mykey
Response: 
VALUE mykey 0 5
hello
END
