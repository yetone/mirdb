MirDB

A Persistent Key-Value Store with Memcached Protocol Compatibility

Drop-in replacement for memcached with data persistence using LSM tree architecture

Key Features

Memcached Protocol

Full compatibility with the memcached text protocol. Works with existing memcached clients - supports SET, GET, DELETE, ADD, REPLACE, APPEND, and PREPEND commands.

Persistent Storage

Unlike standard memcached, MirDB persists data to disk using SSTables. Your data survives restarts with Write-Ahead Log (WAL) for durability.

LSM Tree Architecture

Built on a Log-Structured Merge-tree architecture with skip list memtables, background compaction, and multi-level storage optimization.

Async I/O with Tokio

High-performance async networking powered by Tokio runtime. Efficient block caching with LRU and Snappy compression.

Architecture Overview

Write Request
↓
WAL (Write-Ahead Log)
↓
Memtable (Skip List)
↓
Immutable Memtable
↓
SSTable Level 0
↓
SSTable Levels 1-7

Write Path: Data is first written to the WAL for durability, then inserted into the in-memory Memtable (implemented as a skip list). When the Memtable reaches its size limit, it becomes immutable and is flushed to disk as an SSTable.

Compaction: Background compaction merges SSTables across levels to optimize read performance and reclaim space. Minor compaction flushes memtables to Level 0, while major compaction merges SSTables across levels.

Getting Started

Installation

Clone the repository and build MirDB using Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build the project
cargo build --release

# The binary will be available at target/release/mirdb

Running MirDB

Start the server with the default configuration or specify a custom config file:

# Run with default configuration
cargo run -p mirdb

# Run with custom configuration
cargo run -p mirdb -- -c /path/to/config.toml

# Or use the built binary
./target/release/mirdb -c etc/mirdb.toml

Connecting to MirDB

MirDB listens on 0.0.0.0:12333 by default. Connect using any memcached client or telnet:

# Connect with telnet
telnet localhost 12333

# Or use any memcached client library

Basic Commands

MirDB supports standard memcached commands:

# Set a value (key, flags, exptime, bytes)
set mykey 0 0 5
hello
# Response: STORED

# Get a value
get mykey
# Response: VALUE mykey 0 5
#           hello
#           END

# Delete a value
delete mykey
# Response: DELETED

# Other supported commands: ADD, REPLACE, APPEND, PREPEND

Configuration

MirDB uses TOML configuration files. Here's an example configuration:

# etc/mirdb.toml
addr = "0.0.0.0:12333"

max_level = 7
work_dir = "/tmp/mirdb"

sst_max_size = "100M"
mem_table_max_size = "4M"
mem_table_max_height = 32

imm_mem_table_max_count = 16

block_size = "4K"
block_restart_interval = 16

l0_compaction_trigger = 4

thread_sleep_ms = 500

Configuration Reference

Parameter Description Default
addr Listen address and port 0.0.0.0:12333
work_dir Data directory path /tmp/mirdb
max_level Maximum LSM tree levels 7
mem_table_max_size Max memtable size before flush 4M
sst_max_size Max SSTable file size 100M
block_size Data block size 4K
l0_compaction_trigger Level 0 files before compaction 4

Size values support suffixes: K (KB), M (MB), G (GB), T (TB)
