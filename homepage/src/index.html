MirDB

A Persistent Key-Value Store with Memcached Protocol

High-performance, disk-backed key-value storage built with Rust. Drop-in replacement for Memcached with durability guarantees.

Drop-in Memcached Replacement Disk Persistence LSM-Tree

Features

🔌

Memcached Protocol

Drop-in replacement for memcached with full protocol compatibility. Use your existing memcached clients without any code changes.

💾

Disk Persistence

Unlike traditional memcached, MirDB persists data to disk. Your data survives restarts and power failures.

🌳

LSM-Tree Architecture

Built on log-structured merge-tree architecture with skip list memtable, SSTables, and automatic compaction for optimal performance.

⚡

Async by Default

Powered by Tokio for high-performance async I/O. Handles thousands of concurrent connections efficiently.

🦀

Rust Performance

Written in Rust for memory safety and blazing-fast performance without garbage collection overhead.

Quick Start

Installation

Clone and build MirDB from source using Cargo:

# Clone the repository
$ git clone https://github.com/yetone/mirdb.git
$ cd mirdb

# Build and run
$ cargo run --release

The server will start listening on port 12333 by default.

Usage

Connect using any memcached client or via telnet/nc:

# Connect to MirDB
$ nc localhost 12333

# Store a value
SET mykey 0 0 5
hello
STORED

# Retrieve the value
GET mykey
VALUE mykey 0 5
hello
END

LSM-Tree Architecture

Understanding how MirDB stores and manages data using Log-Structured Merge-Tree architecture.

M Memtable

In-memory data structure using a skip list for fast writes and sorted key lookups. When full, it's flushed to disk as an immutable SSTable.

S SSTable

Sorted String Tables store data on disk in sorted order. Organized in levels (L0, L1, L2...) with increasing size, enabling efficient range queries and lookups.

C Compaction

Background process that merges overlapping SSTables, removes deleted keys, and maintains sorted order. Minor compaction flushes memtable; major compaction merges SSTable levels.

Configuration Reference

MirDB can be configured with the following parameters. Below are the default values and descriptions for each tunable option.

Parameter Default Value Description
listen_address 0.0.0.0:12333 The address and port on which MirDB listens for incoming connections
max_lsm_levels 7 Maximum number of levels in the LSM-tree structure
work_directory /tmp/mirdb Directory where MirDB stores data files and SSTables
sstable_max_size 100MB Maximum size of each SSTable file before compaction
memtable_max_size 4MB Maximum size of the in-memory memtable before flushing to disk
block_size 4KB Size of data blocks within SSTables
