API Reference

MirDB implements the Memcached text protocol, enabling compatibility with existing Memcached clients. Below are the supported commands.

Storage Commands

SET

Store a key-value pair in the database.

set <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n
  • key - The key to store (max 250 characters)
  • flags - 32-bit unsigned integer for client use
  • ttl - Time-to-live in seconds (0 = no expiration)
  • bytes - Size of the data block

Response: STORED on success, NOT_STORED on failure

ADD

Store a key-value pair only if the key does not already exist.

Response: STORED on success, NOT_STORED if key exists

REPLACE

Store a key-value pair only if the key already exists.

Response: STORED on success, NOT_STORED if key doesn't exist

Retrieval Commands

GET

Retrieve one or more values by key.

get <key1> [<key2> ...]\r\n

Response:

VALUE <key> <flags> <bytes>\r\n
<data>\r\n
END\r\n

GETS

Retrieve values with CAS (Check-And-Set) token.

Deletion Commands

DELETE

Remove a key from the database.

delete <key> [noreply]\r\n

Response: DELETED on success, NOT_FOUND if key doesn't exist

MirDB-Specific Commands

INFO

Display database status and level information.

info\r\n

MAJOR_COMPACTION

Trigger manual compaction of the LSM-tree storage.

major_compaction\r\n

Response Codes

Code Description
STOREDData stored successfully
NOT_STOREDData not stored (condition not met)
DELETEDKey deleted successfully
NOT_FOUNDKey not found
ERRORUnknown command
CLIENT_ERROR <msg>Client input error
SERVER_ERROR <msg>Server error
