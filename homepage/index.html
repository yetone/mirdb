A Persistent Key-Value Store with Memcached Protocol

Drop-in memcached replacement with durable storage, powered by Rust and LSM tree architecture

Get Started View on GitHub

Key Features

Built for performance, reliability, and seamless integration with existing infrastructure

Memcached Protocol

Full compatibility with the standard memcached text protocol. Use your existing memcached clients without any code changes.

Persistent Storage

Data survives restarts with LSM tree storage architecture. Your data is durably stored in SSTables on disk.

High Performance

Skip-list memtable provides O(log n) operations for blazing fast reads and writes with efficient memory usage.

Crash Recovery

Write-Ahead Log (WAL) ensures data durability. Recover from unexpected shutdowns without data loss.

Efficient Compaction

Minor and major compaction keeps your storage optimized. Automatic background processes maintain read performance.

Distributed Ready

Designed with distributed operation in mind. Raft consensus support planned for high availability deployments.

Getting Started

Get MirDB running in under 5 minutes with these simple steps.

1

Install MirDB

Install the MirDB server using Cargo, Rust's package manager. Make sure you have Rust installed first. 

$ cargo install mirdb-server
2

Start the Server

Run the MirDB server with default configuration. It will listen on port 12333 by default. 

$ mirdb-server

Listening on: 0.0.0.0:12333
Data directory: /tmp/mirdb
Memtable max size: 4MB
SSTable max size: 100MB
Server ready to accept connections...
3

Basic Usage

Connect to MirDB using telnet or netcat and start using Memcached commands. MirDB supports the standard Memcached text protocol.

Connect 
$ telnet localhost 12333
# or use netcat:
$ nc localhost 12333
Set a Key 
# Format: set <key> <flags> <exptime> <bytes>\r\n<value>\r\n
set mykey 0 0 5
hello
STORED
Get a Key 
get mykey
VALUE mykey 0 5
hello
END
Delete a Key 
delete mykey
DELETED
4

Default Configuration

MirDB runs with sensible defaults. Here are the default configuration values:

Setting Default Value Description
port 12333 Server listening port
data_dir /tmp/mirdb Data storage directory
memtable_size 4MB Maximum memtable size before flush
sstable_size 100MB Maximum SSTable file size
Custom Configuration 
# Run with custom options
$ mirdb-server --port 11211 --data-dir /var/lib/mirdb

Architecture

Understanding MirDB's LSM tree design

LSM Tree Data Flow

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture for efficient writes and reads. Data flows from memory to disk through multiple levels, optimizing for both performance and durability.

Write Path

When a client sends a write request, the data is first written to the Write-Ahead Log (WAL) for durability, then inserted into the in-memory Memtable. Once the Memtable reaches its size threshold (default 4MB), it becomes immutable and is flushed to disk as a new SSTable in Level 0.

Read Path

Reads check the Memtable first for the most recent data, then search through SSTables from Level 0 to Level N. Bloom filters on each SSTable help skip files that don't contain the requested key, significantly improving read performance.

Compaction Process

Compaction merges and reorganizes SSTables to maintain read performance and reclaim space from deleted keys.

Minor Compaction

Flushes the immutable Memtable to Level 0. Creates new SSTables without merging existing ones. Fast and triggered when Memtable is full.

Major Compaction

Merges SSTables from Level N to Level N+1. Removes deleted keys and duplicate entries. Runs in background to optimize storage and read performance.

Core Components

MirDB is organized into modular crates, each handling a specific part of the storage engine.

mirdb-server

The main server crate implementing the Memcached text protocol. Handles client connections, command parsing, and orchestrates the storage engine operations.

skip-list

High-performance concurrent skip-list implementation used for the Memtable. Provides O(log n) insertion, deletion, and lookup operations with lock-free reads.

sstable

SSTable (Sorted String Table) implementation for persistent storage. Manages on-disk data format, block compression, bloom filters, and index structures.

Code Examples

Connect to MirDB using your favorite language

Python Using pymemcache 
from pymemcache.client.base import Client

# Connect to MirDB server
client = Client(('localhost', 12333))

# Set a value
client.set('user:1', '{"name": "Alice", "role": "admin"}')

# Get a value
result = client.get('user:1')
print(result)  # b'{"name": "Alice", "role": "admin"}'

# Delete a value
client.delete('user:1')

# Close the connection
client.close()
Go Using gomemcache 
package main

import (
    "fmt"
    "github.com/bradfitz/gomemcache/memcache"
)

func main() {
    // Connect to MirDB server
    mc := memcache.New("localhost:12333")

    // Set a value
    err := mc.Set(&memcache.Item{
        Key:   "user:1",
        Value: []byte(`{"name": "Alice", "role": "admin"}`),
    })
    if err != nil {
        panic(err)
    }

    // Get a value
    item, err := mc.Get("user:1")
    if err != nil {
        panic(err)
    }
    fmt.Println(string(item.Value))

    // Delete a value
    mc.Delete("user:1")
}
Node.js Using memjs 
const memjs = require('memjs');

// Connect to MirDB server
const client = memjs.Client.create('localhost:12333');

async function main() {
    // Set a value
    await client.set('user:1', '{"name": "Alice", "role": "admin"}');

    // Get a value
    const { value } = await client.get('user:1');
    console.log(value.toString());  // {"name": "Alice", "role": "admin"}

    // Delete a value
    await client.delete('user:1');

    // Close the connection
    client.close();
}

main().catch(console.error);
