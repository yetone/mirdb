Usage Examples

MirDB uses the standard Memcached protocol. Use any Memcached client to interact with your data.

SET Store a Value

Store a key-value pair with optional TTL (time-to-live) in seconds.

Memcached Protocol 
set mykey 0 3600 11
Hello World

# Response:
STORED

Syntax: set <key> <flags> <ttl> <bytes>

GET Retrieve a Value

Retrieve one or more values by their keys.

Memcached Protocol 
get mykey

# Response:
VALUE mykey 0 11
Hello World
END

Syntax: get <key1> [<key2> ...]

DELETE Remove a Key

Delete a key and its associated value from the store.

Memcached Protocol 
delete mykey

# Response:
DELETED

Syntax: delete <key> [noreply]

Using with Python

Use any standard Memcached client library to connect to MirDB.

Python 
from pymemcache.client import base

# Connect to MirDB (default port 12333)
client = base.Client(('localhost', 12333))

# Store a value
client.set('user:123', 'John Doe')

# Retrieve a value
name = client.get('user:123')
print(name)  # b'John Doe'

# Delete a key
client.delete('user:123')

Architecture

MirDB uses an LSM (Log-Structured Merge) tree architecture for optimal write performance with efficient reads.

Memtable

In-memory write buffer implemented as a skip list data structure. All writes go here first, providing O(log n) insert and lookup performance. The skip list maintains sorted order for efficient sequential access.

  • Skip list with configurable max height (default 32)
  • Thread-safe with RwLock synchronization
  • Flushes to disk when reaching 4MB threshold

SSTable

Sorted String Tables provide persistent storage on disk. Data is organized into blocks with prefix compression, checksums, and optional Snappy compression for space efficiency.

  • Block-based format with 4KB default block size
  • Cuckoo filter for fast negative lookups
  • LRU block cache for repeated reads

Multi-Level Compaction

Background compaction merges and compacts data across levels. Minor compaction flushes memtables to Level 0, while major compaction merges SSTables between levels.

  • Level 0 triggers at 4 files (may overlap)
  • Higher levels: sorted, non-overlapping within level
  • Size ratio: 10MB * 10^level threshold

Write-Ahead Log

Every write is first appended to the WAL before being applied to the memtable. This ensures durability and enables crash recovery by replaying uncommitted writes.

  • Sequential append-only writes for durability
  • Enables crash recovery and data integrity
  • Cleaned up after successful memtable flush

Data Flow

1
Write

Data appended to WAL, then inserted into memtable

2
Flush

Full memtable becomes immutable and flushes to Level 0

3
Compact

Background threads merge SSTables down through levels

4
Read

Search memtable, then Level 0, then lower levels

Installation

Get started with MirDB in minutes. Choose your preferred installation method.

Build from Source

  1. Clone the repository

    git clone https://github.com/durbanlegend/mirdb.git

  2. Navigate to the project directory

    cd mirdb

  3. Build the release binary

    cargo build --release

  4. Run MirDB

    ./target/release/mirdb

Using Cargo Install

  1. Install directly from crates.io (when available)

    cargo install mirdb

  2. Or install directly from GitHub

    cargo install --git https://github.com/durbanlegend/mirdb.git

  3. Run MirDB (binary added to PATH)

    mirdb

Default Configuration

MirDB runs with sensible defaults out of the box:

Setting Default Value Description
Port 12333 The TCP port MirDB listens on (Memcached protocol)
Work Directory /tmp/mirdb Directory for SSTable files and write-ahead log
Bind Address 0.0.0.0 Network interface to bind to
