MirDB

A Persistent Key-Value Store with Memcached Protocol

High-performance key-value storage engine built with Rust. Drop-in compatible with Memcached clients, backed by an LSM tree for durability.

Key Features

Tokio Async Runtime

Built on Tokio for blazing-fast asynchronous I/O. Handle thousands of concurrent connections with minimal overhead using Rust's async/await.

Memcached Protocol

Drop-in compatible with existing Memcached clients. Use your favorite language's Memcached library - GET, SET, DELETE commands work out of the box.

Skip-list Memtable

In-memory writes use a high-performance skip-list data structure for O(log n) insertions and lookups, ensuring fast write throughput.

Minor & Major Compaction

LSM tree compaction strategies keep storage efficient. Minor compaction merges memtables to L0, while major compaction optimizes deeper levels.

Quick Start

Installation

bash 
# Clone and build MirDB
git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

# Run the server
./target/release/mirdb-server

Basic Usage

memcached 
# Connect to MirDB (default port: 12333)
telnet localhost 12333

# Store a value (SET key flags exptime bytes)
SET mykey 0 0 5
hello
STORED

# Retrieve the value
GET mykey
VALUE mykey 0 5
hello
END

# Delete the key
DELETE mykey
DELETED

LSM Tree Architecture

How LSM Trees Work

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture optimized for write-heavy workloads while maintaining efficient reads.

  • Write-Ahead Log (WAL): Ensures durability by logging every write before applying it
  • Memtable: Fast in-memory skip-list for active writes with O(log n) operations
  • Immutable Memtables: Frozen memtables queued for compaction to disk
  • Level 0 SSTables: Recently flushed data, may have overlapping key ranges
  • Level 1+ SSTables: Sorted, non-overlapping files for efficient range queries

Minor compaction flushes memtables to Level 0, while major compaction merges and sorts data across levels for optimal read performance.
