MirDB

A persistent key-value store with Memcached protocol support

Drop-in replacement for memcached with disk persistence. Built with Rust for reliability and performance using LSM tree architecture.

Get Started View on GitHub

Key Features

Memcached Protocol

Full compatibility with the standard memcached text protocol. Use your existing memcached clients seamlessly.

Disk Persistence

Unlike in-memory-only memcached, MirDB persists data to disk using SSTables for durability.

LSM Tree Architecture

Log-Structured Merge-tree with multi-level compaction for efficient writes and reads.

Async Networking

Tokio-based async networking for high-performance concurrent connections.

Configurable Parameters

Fine-tune performance with configurable parameters including memtable size, block size, compaction levels, and more.

Architecture Overview

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture optimized for write-heavy workloads. LSM trees provide high write throughput by buffering writes in memory before flushing to disk in sorted batches.

How It Works

  • Write-Ahead Log (WAL): All writes are first recorded in the WAL for durability and crash recovery.
  • Memtable: Writes are buffered in an in-memory skip list for fast access.
  • Immutable Memtables: When the memtable is full, it becomes immutable and queues for compaction.
  • SSTable Levels: Data is organized into sorted string tables across multiple levels, with compaction merging data from lower to higher levels.

Benefits of LSM Trees

  • High Write Throughput: Sequential writes to disk are much faster than random writes.
  • Space Efficiency: Compaction removes duplicate keys and deleted entries.
  • Predictable Performance: Background compaction keeps read latency stable.

Quick Start

# Install MirDB
cargo install mirdb

# Start the server
mirdb -c /path/to/config.toml

# Connect using any memcached client
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello

# Get a value
get mykey
