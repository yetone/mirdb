MirDB

A Persistent Key-Value Store with Memcached Protocol

Drop-in replacement for Memcached with persistence. Built on LSM Tree architecture for high-performance storage that survives restarts.

Key Features

MirDB combines the simplicity of Memcached with the durability of persistent storage.

Memcached Protocol

Full compatibility with the standard memcached text protocol. Use your existing memcached clients and tools seamlessly - no code changes required. Supports SET, GET, DELETE, and more.

Persistence

Unlike traditional memcached, MirDB persists your data to disk using SSTables (Sorted String Tables). Your data survives restarts and crashes with write-ahead logging for durability.

LSM Tree Architecture

Built on a Log-Structured Merge-tree design with in-memory memtables and tiered SSTable levels. Optimized for write-heavy workloads while maintaining efficient reads through level organization.

Compaction

Automatic background compaction maintains optimal performance. Minor compaction flushes memtables to Level 0, while major compaction merges SSTables across levels to reclaim space.

Architecture

MirDB is built on a Log-Structured Merge-tree (LSM Tree) storage engine, optimized for write-heavy workloads while maintaining efficient reads.

Memtable

The memtable is an in-memory write buffer implemented as a skip list data structure. All incoming writes are first recorded here, providing O(log n) insert and lookup performance. When the memtable reaches its configured size threshold (default 4MB), it becomes immutable and is queued for flushing to disk.

  • In-memory skip list for fast writes
  • Configurable size threshold
  • Supports concurrent read access

SSTable

SSTable (Sorted String Table) is the persistent on-disk storage format used by MirDB. Data is organized into sorted, immutable files with block-based structure for efficient random access. Each SSTable includes a cuckoo filter for fast negative lookups and supports Snappy compression.

  • Sorted String Table for disk persistence
  • Block-based format with index
  • Cuckoo filter for bloom-like lookups
  • Snappy compression support

Write-Ahead Log (WAL)

The Write-Ahead Log (WAL) ensures durability by persisting every write to disk before acknowledging it. In the event of a crash, the WAL enables complete crash recovery by replaying uncommitted operations. WAL segments correspond to memtables and are cleaned up after successful compaction.

  • Write-ahead logging for durability
  • Crash recovery via log replay
  • Snappy-compressed records
  • Automatic segment cleanup

Compaction

MirDB uses a two-phase compaction strategy to maintain optimal performance. Minor compaction flushes immutable memtables to Level 0 SSTables. Major compaction (level compaction) merges SSTables across levels, eliminating duplicates and maintaining sorted order within each level.

  • Minor compaction: memtable to Level 0 SSTable
  • Major compaction: level-based merging
  • Background threads for non-blocking operation
  • Configurable triggers and thresholds

Read Path

When reading a key, MirDB searches in order of recency: first the active memtable, then immutable memtables (newest first), and finally SSTable levels starting from Level 0. Level 0 uses linear search (files may overlap), while Level 1+ uses binary search within sorted, non-overlapping files.
