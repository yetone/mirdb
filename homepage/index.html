MirDB

A Persistent Key-Value Store with Memcached Protocol

Get Started View on GitHub

Quick Start

Installation

cargo install mirdb-server

Basic Usage

MirDB uses the standard memcached text protocol, so you can use any memcached client:

# Start the server
mirdb-server

# Connect using telnet or nc
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get a value
get mykey
VALUE mykey 0 5
hello
END

Key Features

Memcached Protocol

Compatible with standard memcached text protocol. Use existing memcached clients seamlessly.

Persistent Storage

Unlike memcached, MirDB persists data to disk using SSTables (Sorted String Tables).

LSM Tree Architecture

Uses Log-Structured Merge-tree approach with memtables and multi-level SSTable compaction.

Async Networking

Built on Tokio for high-performance async I/O operations.

Architecture Overview

MirDB uses an LSM (Log-Structured Merge) tree architecture for efficient write performance and persistent storage.

Write Path

When data is written to MirDB, it follows this path to ensure durability and performance:

  1. WAL (Write-Ahead Log) - Data is first written to the WAL for crash recovery and durability
  2. Memtable - Data is then inserted into the active in-memory skip list for fast access
  3. Immutable Memtables - When the memtable reaches its size limit (default 4MB), it becomes immutable and is queued for flushing
  4. Level 0 SSTables - Minor compaction flushes immutable memtables to Level 0 SSTables on disk
  5. Higher Level SSTables - Major compaction merges and sorts data into higher levels (Level 1+) with non-overlapping key ranges

Read Path

Read operations search for data in order of recency to optimize for recently written data:

  1. Memtable - First checks the active memtable for the most recent writes
  2. Immutable Memtables - Then searches immutable memtables (newest first) awaiting compaction
  3. SSTables - Finally searches SSTable levels starting from Level 0, using binary search for sorted levels (L1+)

Configuration

MirDB is highly configurable. Here are the default settings:

addr = "0.0.0.0:12333"
max_level = 7
work_dir = "/tmp/mirdb"
sst_max_size = "100M"
mem_table_max_size = "4M"
block_size = "4K"

Commands Reference

MirDB supports the standard memcached text protocol commands, plus MirDB-specific administrative commands.

Storage Commands

Command Description Syntax
SET Store a key-value pair set <key> <flags> <ttl> <bytes> [noreply]\r\n<data>\r\n
ADD Store only if key doesn't exist add <key> <flags> <ttl> <bytes> [noreply]\r\n<data>\r\n
REPLACE Store only if key exists replace <key> <flags> <ttl> <bytes> [noreply]\r\n<data>\r\n
APPEND Append data to existing value append <key> <flags> <ttl> <bytes> [noreply]\r\n<data>\r\n
PREPEND Prepend data to existing value prepend <key> <flags> <ttl> <bytes> [noreply]\r\n<data>\r\n

Retrieval Commands

Command Description Syntax
GET Retrieve one or more keys get <key1> [<key2> ...]\r\n
GETS Retrieve with CAS token gets <key1> [<key2> ...]\r\n

Deletion Commands

Command Description Syntax
DELETE Remove a key delete <key> [noreply]\r\n

Administrative Commands (MirDB-Specific)

Command Description Syntax
INFO Display database status and level information info\r\n
MAJOR_COMPACTION Trigger manual compaction major_compaction\r\n
