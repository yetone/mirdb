MirDB: Persistent Key-Value Store

A Memcached-compatible protocol with persistent disk storage. Drop-in replacement that persists your data using LSM tree architecture.

Try Demo Get Started

Core Features

Built on proven database principles for reliable, high-performance key-value storage.

Memcached Protocol

Full compatibility with Memcached text protocol. Use your existing clients and libraries without any code changes.

Persistent Storage

Data persists to disk using SSTables (Sorted String Tables), ensuring your data survives restarts and crashes.

LSM Tree Architecture

Log-Structured Merge Tree design provides optimal write performance while maintaining efficient reads.

Skip List Memtable

In-memory Memtable uses skip list data structure for O(log n) insertions and lookups with minimal overhead.

Multi-level Compaction

Automatic SSTable compaction across multiple levels optimizes storage space and maintains read performance.

Async Performance

Built with Rust and Tokio for high-performance async I/O, handling thousands of concurrent connections efficiently.

Code Examples

MirDB uses the Memcached text protocol. Here are common commands to get you started.

SET Command 
SET mykey 0 0 5
hello

# Response:
STORED
GET Command 
GET mykey

# Response:
VALUE mykey 0 5
hello
END
DELETE Command 
DELETE mykey

# Response:
DELETED

Quick Start

Get MirDB running in minutes with these simple steps

1

Clone the Repository

git clone https://github.com/example/mirdb.git
cd mirdb

Or install via Cargo:

cargo install mirdb
2

Build MirDB

cargo build --release
3

Run MirDB

./target/release/mirdb -c etc/mirdb.toml

MirDB will start listening on 0.0.0.0:12333 by default.

Configuration Options

Customize MirDB with these configuration parameters in your TOML file:

Parameter Description Default
addr Listen address and port 0.0.0.0:12333
work_dir Data directory path /tmp/mirdb
max_level Maximum LSM tree levels 7
mem_table_max_size Max memtable size before flush 4M
sst_max_size Max SSTable file size 100M
block_size Data block size 4K

Example Configuration

# etc/mirdb.toml
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"
max_level = 7
mem_table_max_size = "4M"
sst_max_size = "100M"
block_size = "4K"
