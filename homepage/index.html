MirDB

A Persistent Key-Value Store with Memcached Protocol

Drop-in replacement for Memcached with persistence. Built on LSM Tree architecture for high-performance storage that survives restarts.

Quick Start
Scroll

Key Features

MirDB combines the simplicity of Memcached with the durability of persistent storage.

Memcached Protocol

Full compatibility with the standard memcached text protocol. Use your existing memcached clients and tools seamlessly - no code changes required. Supports SET, GET, DELETE, and more.

Persistence

Unlike traditional memcached, MirDB persists your data to disk using SSTables (Sorted String Tables). Your data survives restarts and crashes with write-ahead logging for durability.

LSM Tree Architecture

Built on a Log-Structured Merge-tree design with in-memory memtables and tiered SSTable levels. Optimized for write-heavy workloads while maintaining efficient reads through level organization.

Compaction

Automatic background compaction maintains optimal performance. Minor compaction flushes memtables to Level 0, while major compaction merges SSTables across levels to reclaim space.

Quick Start

Get MirDB up and running in minutes with these simple steps.

1

Install MirDB

Clone the repository and build from source using Cargo, Rust's package manager.

bash 
# Clone the repository
git clone https://github.com/example/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release
2

Start the Server

Launch MirDB with a configuration file. The server listens on port 12333 by default.

bash 
# Start MirDB with config file
mirdb -c config.toml

# Or use the default configuration
./target/release/mirdb-server -c etc/mirdb.toml
3

Connect and Use

Use any Memcached client or telnet to connect. MirDB supports standard SET and GET commands.

bash 
# Connect using telnet
telnet localhost 12333

# Store a value (SET key flags ttl bytes)
set mykey 0 0 5
hello
# Response: STORED

# Retrieve the value
get mykey
# Response: VALUE mykey 0 5
#           hello
#           END

Sample Configuration

Create a config.toml file to customize MirDB settings:

toml 
# MirDB Configuration
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"
max_level = 7

# Memory settings
mem_table_max_size = "4M"
sst_max_size = "100M"
