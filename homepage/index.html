MirDB

A high-performance, persistent key-value store with Memcached protocol compatibility

Built in Rust with an LSM-tree storage engine for durability and speed. Drop-in replacement for Memcached with persistent storage capabilities.

Key Features

Memcached Compatible

Drop-in replacement supporting get, set, delete, and more standard Memcached commands.

Persistent Storage

LSM-tree architecture with SSTable files for durable data storage.

Write-Ahead Logging

Never lose data with WAL-based crash recovery.

High Performance

Skip list memtables and LRU block cache for fast operations.

Efficient Compression

Snappy compression reduces storage footprint.

Smart Filtering

Cuckoo filters minimize unnecessary disk reads.

How It Works

MirDB uses a Log-Structured Merge-tree (LSM-tree) architecture for efficient storage and retrieval of key-value data.

Write Path

When data is written to MirDB, it follows a carefully designed path for both durability and performance:

  1. Write-Ahead Log (WAL): Every write is first recorded in the WAL for crash recovery and durability.
  2. Mutable Memtable: The write is then inserted into an in-memory skip list structure for fast access.
  3. Immutable Memtable: When the memtable reaches its size threshold, it becomes immutable and is queued for flushing.
  4. SSTable Files: Background threads flush immutable memtables to sorted SSTable files on disk.

Read Path

Reading data from MirDB is optimized to find the most recent value as quickly as possible:

  1. Mutable Memtable: The current in-memory memtable is checked first for the fastest response.
  2. Immutable Memtables: If not found, immutable memtables are searched from newest to oldest.
  3. SSTable Levels: The search continues through SSTable files, level by level (L0 to L7).
  4. Cuckoo Filter: Each SSTable uses a Cuckoo filter to quickly skip files that don't contain the key.

Memcached Commands

MirDB supports standard Memcached protocol commands. Here are the most commonly used operations:

get <key>

Retrieve a value by its key. Returns the stored value or nothing if the key doesn't exist.

get mykey

set <key> <value>

Store a value with the specified key. Overwrites any existing value.

set mykey 0 0 5
hello

delete <key>

Remove a key and its associated value from the store.

delete mykey

gets <key>

Retrieve a value with its CAS (Check-And-Set) token for optimistic locking.

gets mykey

add <key> <value>

Store a value only if the key doesn't already exist.

add newkey 0 0 5
world

replace <key> <value>

Update a value only if the key already exists.

replace mykey 0 0 6
world!

append <key> <data>

Append data to an existing value.

append mykey 0 0 6
_suffix

prepend <key> <data>

Prepend data to an existing value.

prepend mykey 0 0 7
prefix_

Getting Started

Installation

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release

# Run the server
./target/release/mirdb-server

Quick Configuration

Create a configuration file at etc/mirdb.toml: 

# MirDB Configuration
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"

# Memory settings
mem_table_max_size = "4M"
mem_table_max_height = 32

# Storage settings
sst_max_size = "100M"
block_size = "4K"

# LSM-tree settings
max_level = 7
l0_compaction_trigger = 4
