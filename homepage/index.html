MirDB

Persistent memcached, powered by Rust

A high-performance key-value store that combines the simplicity of the memcached protocol with durable storage using LSM tree architecture.

Key Features

Memcached Protocol

Drop-in replacement for memcached. Works with existing clients and tooling.

Persistent Storage

Data persists to disk using SSTables. Survives restarts and crashes.

LSM Tree Architecture

Write-optimized storage with efficient compaction for consistent performance.

Built with Rust

Memory-safe implementation with high performance and reliability.

Log-Structured Merge Tree

MirDB uses an LSM (Log-Structured Merge) tree architecture, which is optimized for write-heavy workloads. All writes first go to the Write-Ahead Log (WAL) for durability, then to an in-memory Memtable for fast access.

When the Memtable fills up, it becomes immutable and is flushed to disk as an SSTable (Sorted String Table). Background compaction processes merge and sort these SSTables across levels, maintaining read performance while optimizing storage efficiency.

This design provides excellent write performance, crash recovery through WAL, and efficient reads through bloom filters and block indexes in each SSTable.

Getting Started

Installation

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build the project
cargo build --release

# Run MirDB server
./target/release/mirdb-server

Basic Usage

# Connect using telnet or any memcached client
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get a value
get mykey
VALUE mykey 0 5
hello
END

# Delete a value
delete mykey
DELETED

Configuration

Parameter Default Description
listen_addr 0.0.0.0:12333 Server listen address
max_levels 7 Maximum LSM tree levels
work_dir /tmp/mirdb Data storage directory
sstable_max_size 100M Maximum SSTable file size
memtable_max_size 4M Maximum memtable size before flush
