MirDB

Persistent Key-Value Store with Memcached Protocol

A high-performance key-value store that combines the simplicity of the Memcached protocol with the durability of persistent storage. Built with Rust for reliability and speed.

Get Started View on GitHub

Key Features

Memcached Compatible

Use existing memcached clients and libraries. Drop-in replacement with zero code changes. Supports GET, SET, DELETE, and other standard commands.

Built-in Persistence

Unlike memcached, your data survives restarts. SSTables (Sorted String Tables) ensure durability without sacrificing speed.

LSM-Tree Architecture

Write-optimized storage engine with automatic compaction. Handles high write throughput efficiently using Log-Structured Merge-tree design.

Simple Configuration

TOML-based configuration with sensible defaults. Get started with minimal setup and customize as needed.

Quick Start

# Start MirDB server
mirdb -c /path/to/config.toml

# Connect with any memcached client
telnet localhost 12333

# Store a value
set mykey 0 0 5
hello
STORED

# Retrieve the value
get mykey
VALUE mykey 0 5
hello
END

Getting Started

1. Install

cargo install mirdb

2. Configure

# config.toml
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"
max_level = 7
sst_max_size = "100M"
mem_table_max_size = "4M"
block_size = "4K"

3. Run

mirdb -c config.toml

Default Configuration Values

Parameter Default Value
Listen Address 0.0.0.0:12333

Work Directory /tmp/mirdb
SSTable Max Size 100MB
Memtable Max Size 4MB

Architecture

MirDB uses an LSM-tree (Log-Structured Merge-tree) architecture optimized for high write throughput while maintaining excellent read performance. This architecture provides durability through write-ahead logging and efficient storage through automatic compaction.

LSM-Tree Benefits

  • Write Optimization: Sequential writes to WAL and Memtable provide high write throughput
  • Durability: Write-Ahead Log (WAL) ensures data survives crashes before reaching SSTables
  • Efficient Storage: Automatic compaction merges and sorts data, reclaiming space from deleted entries
  • Read Performance: Bloom filters and sorted SSTables enable fast key lookups
