The diagram shows MirDB's LSM tree architecture with two main paths: Write Path: Client sends data to MirDB Server, which writes to Write-Ahead Log (WAL), then to Memtable (Skip List), when full becomes Immutable Memtable, then minor compaction to SSTable Level 0, and major compaction to deeper levels. Read Path: Client queries MirDB Server, which checks Memtable first, then Immutable Memtables if not found, finally checks SSTable levels from L0 to L2+ until value is found.

Write Path

MirDB uses a Log-Structured Merge (LSM) tree for efficient write operations:

  1. WAL (Write-Ahead Log): Every write operation is first recorded in the WAL for durability. This ensures data can be recovered after crashes.
  2. Memtable: Data is written to an in-memory skip list structure called the Memtable for fast write and lookup performance.
  3. Immutable Memtable: When the Memtable reaches its size limit, it becomes immutable and a new Memtable is created for incoming writes.
  4. SSTables: Immutable Memtables are flushed to disk as Sorted String Tables (SSTables), organized in levels for efficient storage.

Read Path

Reads follow a specific lookup order to find the most recent value:

  1. Memtable: First, MirDB checks the active Memtable for the requested key, as it contains the most recent writes.
  2. Immutable Memtables: If not found, the search continues through any Immutable Memtables awaiting flush to disk.
  3. SSTable Levels: Finally, MirDB searches through SSTable levels from L0 to deeper levels (L1, L2, etc.) until the key is found or confirmed absent.

Compaction Process

Compaction maintains storage efficiency and read performance:

Minor Compaction

When Immutable Memtables accumulate, they are flushed to SSTable Level 0. This process converts in-memory data to persistent disk storage while maintaining sorted order within each SSTable.

Major Compaction

When a level accumulates too many SSTables, major compaction merges them into the next level. This process removes deleted keys, merges duplicate entries, and maintains sorted order across levels for efficient range queries.
