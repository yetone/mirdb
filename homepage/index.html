MirDB

A Persistent Key-Value Store with Memcached Protocol Compatibility

Drop-in replacement for Memcached with built-in persistence using LSM Tree architecture.

Get Started View on GitHub

Key Features

🔌

Memcached Protocol Compatible

Use your existing Memcached clients without modification. MirDB implements the standard Memcached text protocol, enabling seamless migration and drop-in replacement for your caching layer.

💾

Persistent & Durable Storage

Unlike standard Memcached, MirDB persists your data to disk using SSTables (Sorted String Tables). Your data survives restarts and crashes with built-in durability guarantees.

🌲

LSM Tree Architecture

Built on a Log-Structured Merge (LSM) tree design with in-memory memtables and multi-level compaction. Optimized for write-heavy workloads while maintaining excellent read performance.

⚡

High Performance

Powered by Rust and Tokio for async I/O. Features efficient skip-list memtables, background compaction threads, and optimized SSTable indexing for fast key lookups.

Architecture Overview

MirDB uses a Log-Structured Merge (LSM) Tree architecture to provide both high write throughput and durable persistence.

LSM Tree Structure

The Log-Structured Merge (LSM) Tree is a data structure optimized for write-heavy workloads. Instead of updating data in place, writes are buffered in memory and periodically flushed to disk in sorted batches, minimizing random I/O.

Memtables

Incoming writes are first stored in an in-memory data structure called a memtable. MirDB uses a skip-list based memtable for efficient sorted inserts and lookups. When the memtable reaches a size threshold, it becomes immutable and is flushed to disk.

SSTables (Sorted String Tables)

When memtables are flushed to disk, they become SSTables—immutable, sorted files containing key-value pairs. SSTables include an index for fast key lookups and bloom filters to quickly determine if a key might exist in the file.

Compaction Strategy

Over time, multiple SSTables accumulate at each level. MirDB runs background compaction to merge overlapping SSTables, remove deleted entries, and consolidate data into fewer, larger files. This keeps read performance optimal and reclaims disk space.

Quick Start

Get started with MirDB in minutes. Follow these simple steps to install and start using MirDB.

Installation

  1. Clone the repository 
    git clone https://github.com/mirdb/mirdb.git
cd mirdb
  2. Build the project 
    cargo build --release
  3. Start the server 
    ./target/release/mirdb --data-dir ./data

Basic Usage

Connect using any Memcached client. Here's an example using Python:

# Install pymemcache client
# pip install pymemcache

from pymemcache.client import base

# Connect to MirDB (default port 11211)
client = base.Client(('localhost', 11211))

# Set a value
client.set('user:1', 'Alice')

# Get the value
result = client.get('user:1')
print(result)  # Output: b'Alice'

# Set with expiration (60 seconds)
client.set('session:abc', 'data', expire=60)

# Delete a key
client.delete('user:1')

For more details, configuration options, and advanced usage, see the full documentation.
