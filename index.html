MirDB

A Persistent Key-Value Store with Memcached Protocol

MirDB is a high-performance, persistent key-value store written in Rust. It implements the Memcached protocol, allowing seamless integration with existing memcached clients while providing durable disk-based storage.

View on GitHub Documentation

Key Features

Memcached Compatible

Full compatibility with the Memcached text protocol. Use your existing memcached clients seamlessly without any code changes. Supports GET, SET, DELETE, ADD, REPLACE, APPEND, and PREPEND commands.

Persistent Storage

Unlike traditional memcached, your data survives restarts. MirDB uses SSTable-based storage with Write-Ahead Logging (WAL) to ensure data durability and crash recovery.

LSM Tree Architecture

Built on a Log-Structured Merge-tree architecture with Tokio async I/O for high performance. Features memtables with skip lists, multi-level compaction, and efficient read/write paths.

Quick Start

Get up and running with MirDB in minutes. Start the server and begin storing data using familiar memcached commands.

Start the Server

# Start MirDB server with configuration file
mirdb -c /path/to/config.toml

Basic Usage

# Connect with any memcached client
$ telnet localhost 12333

# SET operation - store a value
> set mykey 0 0 5
> hello
STORED

# GET operation - retrieve a value
> get mykey
VALUE mykey 0 5
hello
END

Configuration

# config.toml
addr = "0.0.0.0:12333"
max_level = 7
work_dir = "/var/lib/mirdb"
mem_table_max_size = "4M"
sst_max_size = "100M"

Architecture Overview

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture optimized for write-heavy workloads. Data flows through multiple stages to ensure both high performance and durability.

Write Path

  1. WAL (Write-Ahead Log): All writes are first recorded to the Write-Ahead Log for durability. This ensures data can be recovered even after a crash.
  2. Memtable: Data is then written to an in-memory structure (skip list) for fast access. The Memtable provides O(log n) read and write operations.
  3. SSTable (Sorted String Table): When the Memtable reaches capacity (default 4MB), it's flushed to disk as an immutable SSTable file. SSTables are organized in multiple levels with background compaction to optimize read performance.

Supported Commands

MirDB implements the memcached text protocol. Here are the supported commands:

Storage Commands

SET Store a key-value pair
ADD Store only if key doesn't exist
REPLACE Store only if key exists
APPEND Append data to existing value
PREPEND Prepend data to existing value

Retrieval Commands

GET Retrieve one or more keys
GETS Retrieve with CAS token

Deletion Commands

DELETE Remove a key from the store
