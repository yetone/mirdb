MirDB

A persistent key-value store with Memcached protocol compatibility

Fast, durable, and powered by Rust

Get Started View on GitHub
Rust Memcached Protocol LSM-tree

Features

Memcached Protocol

Drop-in compatibility with existing Memcached clients using the standard text protocol. Supports get, gets, set, add, replace, append, prepend, and delete commands.

Skip List Memtable

High-performance in-memory operations using a custom skip list data structure for fast reads and writes.

LSM-tree Storage

Log-Structured Merge-tree architecture with SSTable files for efficient persistent storage and compaction.

Write-Ahead Logging

Durability guaranteed through write-ahead logging (WAL), ensuring data survives crashes and restarts.

Snappy Compression

Efficient storage with Snappy compression, reducing disk footprint without sacrificing performance.

Cuckoo Filter

Fast key existence checks using Cuckoo filters, minimizing unnecessary disk reads for non-existent keys.

Supported Commands

Command Description
get Retrieve one or more values by key
gets Retrieve values with CAS token
set Store a key-value pair
add Store only if key doesn't exist
replace Store only if key exists
append Append to existing value
prepend Prepend to existing value
delete Remove a key-value pair

Getting Started

1. Install

cargo install mirdb-server

2. Run

mirdb-server --config etc/mirdb.toml

3. Connect

Use any Memcached client to connect:

# Using telnet
telnet localhost 11211

# Set a value
set mykey 0 0 5
hello
STORED

# Get the value
get mykey
VALUE mykey 0 5
hello
END

Architecture

MirDB uses an LSM-tree (Log-Structured Merge-tree) architecture for efficient storage:

Write Request
→
WAL Write-Ahead Log
→
Memtable Skip List
→
SSTable Sorted String Table

1. All writes are first logged to the WAL for durability

2. Data is then written to the in-memory Memtable (skip list)

3. When the Memtable is full, it's flushed to disk as an SSTable

4. Background compaction merges SSTables for read efficiency
