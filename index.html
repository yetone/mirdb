Persistent Memcached for Modern Applications

MirDB brings persistence to the Memcached protocol. Get the simplicity and compatibility of Memcached with the durability of disk-based storage.

Get Started View on GitHub

Features

Memcached Protocol Compatibility

Drop-in replacement for Memcached. Existing clients work without modification using the standard text protocol.

Persistent Storage

Data survives restarts with durable disk-based storage using SSTables (Sorted String Tables).

LSM Tree Architecture

Production-ready Log-Structured Merge-tree ensures data integrity with Write-Ahead Logging.

Async Performance

Built with Tokio for high-throughput async I/O, delivering exceptional performance for modern workloads.

Configurable Storage

Fine-tune memtable sizes, SSTable limits, and compaction parameters to match your use case.

How It Works

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture to provide durable, high-performance key-value storage. Here's how your data flows through the system:

📝

1. Write Request

Client sends SET/ADD/REPLACE command via Memcached protocol

→
📋

2. Write-Ahead Log

Data is first written to WAL for crash recovery and durability

→
🧠

3. Memtable

In-memory skip list provides fast reads and writes

→
💾

4. SSTables

When memtable is full, data is flushed to sorted disk files

LSM Tree Benefits

  • Optimized for write-heavy workloads
  • Sequential disk writes for high throughput
  • Background compaction keeps read performance optimal

Data Integrity

  • Write-Ahead Logging ensures no data loss on crash
  • Immutable SSTables prevent data corruption
  • Multi-level compaction maintains data consistency

Getting Started

1. Build MirDB

cargo build --release

2. Run the Server

./target/release/mirdb-server -c etc/mirdb.toml

3. Connect with Any Memcached Client

telnet localhost 12333
> set mykey 0 0 5
> hello
STORED
> get mykey
VALUE mykey 0 5
hello
END

Documentation

Supported Commands

Command Description
SETStore a key-value pair
GETRetrieve one or more keys
DELETERemove a key
ADDStore only if key doesn't exist
REPLACEStore only if key exists
APPENDAppend data to existing value
PREPENDPrepend data to existing value
INFODisplay database status (MirDB-specific)

Configuration

addr = "0.0.0.0:12333"
work_dir = "/tmp/mirdb"
mem_table_max_size = "4M"
sst_max_size = "100M"
