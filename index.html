What is MirDB?

MirDB is a persistent key-value store written in Rust that implements the Memcached protocol. It combines the simplicity and speed of memcached with the durability of disk-based persistence, making it a drop-in replacement for memcached that ensures your data survives restarts.

Unlike traditional memcached which stores all data in memory and loses everything on restart, MirDB uses an LSM tree architecture with SSTable-based persistence to provide both high-performance caching and reliable data storage. Existing memcached clients connect seamlessly — just point them at MirDB and enjoy the benefits of persistence without changing a single line of client code.

Features

🔌

Memcached Protocol

Full Memcached protocol compatibility means existing clients connect seamlessly. Drop MirDB into your infrastructure without changing a single line of client code.

💾

Persistence

SSTable-based persistence with LSM tree architecture ensures your data survives restarts. Durability meets performance with efficient disk-based storage.

🌳

LSM Tree Architecture

Advanced LSM tree storage engine with minor and major compaction strategies optimizes read and write performance while minimizing storage overhead.

⚡

Async Networking

Built on Tokio, Rust's premier async runtime, MirDB handles thousands of concurrent connections with minimal resource overhead and maximum throughput.

Quick Start

MirDB implements the Memcached text protocol, so any memcached client works out of the box. Here is how to set and retrieve values using a simple telnet session:

Set a key-value pair 
set mykey 0 60 5
hello
STORED
Retrieve a value 
get mykey
VALUE mykey 0 5
hello
END
Using a memcached client (Python example) 
import memcache
client = memcache.Client(['127.0.0.1:12333'])
client.set('mykey', 'hello')
value = client.get('mykey')
print(value)  # Output: hello

Configuration

MirDB uses sensible defaults that work out of the box. These are the default configuration values:

Option Default Value Description
listen address 0.0.0.0:12333 Address the server listens on
max_level 7 Maximum number of LSM tree levels
work_dir /tmp/mirdb Working directory for data files
sst_max_size 100MB Maximum size of an SSTable file
mem_table_max_size 4MB Maximum size of the in-memory write buffer
block_size 4KB Size of each data block in SSTables
mem_table_max_height 32 Maximum height of the skip list memtable
imm_mem_table_max_count 16 Maximum number of immutable memtables
block_restart_interval 16 Restart interval for delta encoding in blocks
l0_compaction_trigger 4 Trigger for L0 level compaction
thread_sleep_ms 500 Background thread sleep interval in milliseconds
