Architecture Overview

Understanding MirDB's LSM Tree storage approach.

LSM Tree Approach

MirDB uses a Log-Structured Merge-tree (LSM Tree) architecture which provides excellent write performance by batching writes and periodically compacting data:

  • Write-Ahead Log (WAL): All write operations are first logged to disk to ensure durability. This prevents data loss on system crashes.
  • Memtable (Skip-List): Writes are buffered in an in-memory sorted data structure (skip-list) for fast writes and reads on recent data. GET requests first check the memtable.
  • SSTables: When the memtable reaches its size limit, it's flushed to disk as an immutable Sorted String Table (SSTable). These files are periodically compacted to optimize storage and eliminate duplicates.

Benefits of LSM Trees

  • Write Efficiency: Sequential writes to log files avoid random disk I/O
  • Persistent Durability: Write-ahead logging ensures data survives crashes
  • Read Performance: Skip-list memtable provides O(log n) lookups
  • Space Efficiency: Compaction reduces storage requirements and eliminates tombstones

Quick Start

Get started with MirDB in minutes.

Installation

Install MirDB by cloning the repository and building with Cargo.

git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

Configuration

Create a mirdb.toml configuration file with the following settings:

[server]
address = "127.0.0.1:11211"
work_dir = "./data"
memtable_size = "64MB"
sstable_max_size = "256MB"

Basic Usage

Connect to MirDB using any memcache client:

import memcache

# Connect to MirDB
client = memcache.Client(['localhost:11211'])

# Set a key-value pair
client.set('key', 'value')

# Get the value
value = client.get('key')
print(value)  # Output: value

Supported Operations

MirDB supports the following Memcached commands:

  • GET - Retrieve the value for a given key
  • GETS - Retrieve the value with CAS token for a given key
  • SET - Store a key-value pair
  • ADD - Store a key-value pair only if the key doesn't exist
  • REPLACE - Replace an existing value for a given key
  • APPEND - Append data to an existing value
  • PREPEND - Prepend data to an existing value
  • DELETE - Delete a key-value pair
  • INFO - Get server information
  • MajorCompaction - Trigger a major compaction for SSTable optimization
