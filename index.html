MirDB

Persistent Key-Value Store with Memcached Protocol

A high-performance, persistent key-value store written in Rust that speaks the Memcached protocol. Drop-in replacement for memcached with the added benefit of data persistence using LSM tree architecture.

Get Started View on GitHub

Key Features

Built with modern Rust for safety and performance

Memcached Protocol

Full compatibility with the memcached text protocol. Use your existing memcached clients without any code changes.

Persistent Storage

Unlike memcached, MirDB persists data to disk using SSTables. Your data survives restarts.

LSM Tree Architecture

Log-Structured Merge-tree design with memtables, immutable memtables, and multi-level SSTable compaction.

Async Networking

Built on Tokio for high-performance asynchronous I/O and efficient connection handling.

Write-Ahead Logging

Durability guaranteed with WAL. Data is safe even in case of unexpected shutdowns.

Configurable Compaction

Fine-tune compaction strategies to optimize for your workload with configurable triggers and levels.

Quick Start

Get MirDB running in minutes

1 Installation

Install MirDB using Cargo or download a pre-built binary:

# Install from source using Cargo
git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

# The binary will be available at ./target/release/mirdb

2 Configuration

Create a configuration file in TOML format:

# mirdb.toml - Basic configuration
addr = "0.0.0.0:12333"
work_dir = "/tmp/mirdb"

max_level = 7
mem_table_max_size = "4M"
sst_max_size = "100M"
block_size = "4K"

l0_compaction_trigger = 4

3 Start the Server

Run MirDB with your configuration file:

# Start MirDB server with custom config
./target/release/mirdb -c mirdb.toml

# Or use the default configuration
./target/release/mirdb

4 Connect a Client

Connect using any memcached-compatible client or simple telnet:

# Connect using telnet
telnet localhost 12333

# Or use netcat
nc localhost 12333

# Try some commands:
set mykey 0 0 5
hello
# Response: STORED

get mykey
# Response: VALUE mykey 0 5
#           hello
#           END

Supported Commands

Full memcached protocol compatibility plus MirDB-specific commands

Storage Commands

  • SET Store a key-value pair
  • ADD Store only if key doesn't exist
  • REPLACE Store only if key exists
  • APPEND Append data to existing value
  • PREPEND Prepend data to existing value

Retrieval Commands

  • GET Retrieve one or more keys
  • GETS Retrieve with CAS token

Deletion Commands

  • DELETE Remove a key

MirDB-Specific

  • INFO Display database status
  • MAJOR_COMPACTION Trigger manual compaction

Configuration Options

Tune MirDB for your specific workload

Parameter Description Default
addr Listen address and port 0.0.0.0:12333
work_dir Data directory path /tmp/mirdb
max_level Maximum LSM tree levels 7
mem_table_max_size Max memtable size before flush 4M
sst_max_size Max SSTable file size 100M
block_size Data block size 4K
l0_compaction_trigger Level 0 files before compaction 4
