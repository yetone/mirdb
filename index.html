MirDB

Persistent Key-Value Store with Memcached Protocol Compatibility

Key Features

🔌

Memcached Protocol Compatible

Works seamlessly with existing memcached clients. Supports standard commands like SET, GET, DELETE, ADD, REPLACE, APPEND, and PREPEND with familiar response codes.

💾

Persistent Storage

Unlike standard memcached, MirDB persists data to disk using SSTables (Sorted String Tables). Your data survives restarts with Write-Ahead Log (WAL) for durability.

🌳

LSM Tree Architecture

Built on a Log-Structured Merge-tree design with memtables, immutable memtables, and multi-level SSTable compaction for optimal write performance and storage efficiency.

⚡

Async I/O with Tokio

High-performance async networking powered by Tokio. Non-blocking I/O operations ensure excellent throughput and low latency for concurrent connections.

⚙️

Highly Configurable

Fine-tune performance with TOML-based configuration. Adjust memtable size, SSTable size, compaction triggers, and more to match your workload.

🚀

Block Caching & Compression

LRU block cache for frequently accessed data and Snappy compression for efficient storage utilization without sacrificing read performance.

Architecture Overview

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture for optimal write performance and storage efficiency.

Write Path

Data is first written to the WAL (Write-Ahead Log) for durability, then inserted into the in-memory Memtable (implemented as a skip list). When the Memtable reaches its size limit, it becomes immutable and is queued for flushing.

Compaction

Background minor compaction flushes immutable memtables to Level 0 SSTables. Major compaction merges SSTables across levels to optimize read performance and reclaim space, maintaining sorted, non-overlapping files at each level.

Getting Started

Installation

cargo build --release

Configuration

Create a configuration file (config.toml):

addr = "0.0.0.0:12333"
max_level = 7
work_dir = "/tmp/mirdb"
sst_max_size = "100M"
mem_table_max_size = "4M"
block_size = "4K"
l0_compaction_trigger = 4

Usage Example

Connect with any memcached client:

# Connect using telnet
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
# Response: STORED

# Get a value
get mykey
# Response: VALUE mykey 0 5
#           hello
#           END

# Delete a value
delete mykey
# Response: DELETED

Configuration Reference

MirDB uses TOML configuration files for flexible customization. Below are the key configuration parameters and their default values.

Parameter Description Default
addr Listen address and port for incoming connections 0.0.0.0:12333
work_dir Data directory path for storing SSTables and WAL /tmp/mirdb
max_level Maximum number of LSM tree levels 7
mem_table_max_size Maximum memtable size before flush to disk 4M
sst_max_size Maximum SSTable file size 100M
block_size Data block size within SSTables 4K
l0_compaction_trigger Number of Level 0 files that trigger compaction 4

Size values support suffixes: K (KB), M (MB), G (GB), T (TB). For full configuration documentation, see the GitHub repository.
