MirDB

Persistent Key-Value Store with Memcached Protocol

Key Features

🔌

Memcached Protocol Compatible

Full compatibility with the standard Memcached text protocol. Connect using existing Memcached clients seamlessly. Supports SET, GET, DELETE, ADD, REPLACE, and more commands.

💾

Persistent Storage with SSTables

Unlike traditional Memcached, MirDB persists your data to disk using SSTables (Sorted String Tables). Your data survives restarts and crashes with full durability.

🌲

LSM Tree Architecture

Built on a Log-Structured Merge Tree (LSM) architecture for efficient write operations. Features multi-level compaction with configurable thresholds for optimal performance.

⚡

Async Networking with Tokio

High-performance asynchronous networking powered by Tokio. Handle thousands of concurrent connections efficiently with Rust's async runtime.

📋

Skip List Memtable

In-memory data stored in a skip list data structure for fast O(log n) insertions and lookups. Efficient memory usage with lock-free concurrent access.

🔄

Automatic Compaction

Background minor and major compaction processes keep your data organized. Level-based compaction reduces read amplification while maintaining write performance.

MirDB vs Memcached

Standard Memcached is a powerful in-memory caching solution, but it's volatile—your data is lost when the server restarts. MirDB provides a drop-in replacement that adds persistence while maintaining full protocol compatibility.

MirDB

  • Persistent storage to disk via SSTables
  • Data survives restarts and crashes
  • Full durability with Write-Ahead Log
  • LSM tree architecture for efficient writes
  • Compatible with existing Memcached clients

Standard Memcached

  • Volatile in-memory storage only
  • Data lost on restart or failure
  • No durability guarantees
  • Simple hash table storage
  • Requires separate persistence layer

Switch seamlessly: MirDB uses the same Memcached protocol, so your existing code and clients work without changes. Get the benefits of persistence with zero migration effort.

Default Configuration

MirDB comes with sensible defaults that work for most use cases. Configuration is managed via TOML files.

Parameter Description Default Value
Port Server listen port 12333
Max LSM Levels Maximum number of LSM tree levels 7
Memtable Size Maximum size before memtable flush 4MB
SSTable Max Size Maximum SSTable file size 100MB
Block Size Data block size for SSTables 4KB
L0 Compaction Trigger Level 0 files before compaction 4

Quick Start

# Clone the repository git clone https://github.com/yetone/mirdb.git cd mirdb # Build the project cargo build --release # Run MirDB server ./target/release/mirdb-server
# Connect using telnet or any Memcached client telnet localhost 12333 # Set a value set mykey 0 0 5 hello # Get the value get mykey
