MirDB

Persistent Key-Value Store with Memcached Protocol

  • Drop-in replacement for memcached with data persistence
  • LSM tree architecture for efficient writes and durability
  • Written in Rust for safety and high performance
Get Started View on GitHub

Key Features

Memcached Compatible

Use your existing memcached clients without modification. MirDB implements the standard memcached text protocol.

Persistent Storage

Unlike memcached, your data survives restarts. MirDB uses SSTables to persist data safely to disk.

LSM Architecture

Log-Structured Merge-tree provides excellent write performance with background compaction for optimized storage.

Async Performance

Built on Tokio for high-throughput async I/O operations, handling thousands of concurrent connections efficiently.

Getting Started

Get MirDB running in under 5 minutes with these simple steps.

1

Install MirDB

Clone the repository and build with Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release
2

Start the Server

Run MirDB with the default configuration:

# Start MirDB server
./target/release/mirdb-server -c etc/mirdb.toml

MirDB listens on 0.0.0.0:12333 by default.

3

Connect to MirDB

Connect using telnet or any memcached client:

# Connect using telnet
telnet localhost 12333
4

Basic Operations

Try these basic SET and GET commands:

# SET a key-value pair
# Format: set <key> <flags> <ttl> <bytes>
set mykey 0 0 5
hello
STORED

# GET the value back
get mykey
VALUE mykey 0 5
hello
END

# DELETE the key
delete mykey
DELETED

Supported Commands

MirDB supports standard memcached commands plus additional MirDB-specific commands.

Storage Commands

  • SET - Store a key-value pair
  • ADD - Store only if key doesn't exist
  • REPLACE - Store only if key exists
  • APPEND - Append data to existing value
  • PREPEND - Prepend data to existing value

Retrieval Commands

  • GET - Retrieve one or more keys
  • GETS - Retrieve with CAS token

Deletion Commands

  • DELETE - Remove a key

MirDB-Specific

  • INFO - Display database status
  • MAJOR_COMPACTION - Trigger manual compaction

Architecture

MirDB uses a Log-Structured Merge-tree (LSM) architecture for efficient writes and persistent storage.

Client Memcached Protocol
↓
WAL Write-Ahead Log
Memtable Skip List (In-Memory)
↓ Minor Compaction
SSTable L0 Sorted String Tables
↓ Major Compaction
SSTable L1-L7 Compacted Levels

How It Works

  1. Write Path: Writes go to the WAL for durability, then to the in-memory Memtable (skip list)
  2. Minor Compaction: When Memtable is full, it's flushed to disk as an immutable SSTable
  3. Major Compaction: SSTables are periodically merged across levels for optimized reads
  4. Read Path: Reads check Memtable first, then search through SSTable levels

Configuration

MirDB can be configured via a TOML file. Here are the default settings:

Parameter Default Value Description
addr 0.0.0.0:12333 Listen address and port
work_dir /tmp/mirdb Data storage directory
mem_table_max_size 4M Maximum memtable size before flush
sst_max_size 100M Maximum SSTable file size
max_level 7 Maximum LSM tree levels
block_size 4K Data block size
