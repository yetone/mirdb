MirDB

Persistent Memcached-compatible key-value store

Drop-in Memcached replacement with persistent storage. Built with Rust for performance and safety, featuring LSM tree architecture for write-optimized workloads.

Get Started View on GitHub

Key Features

Everything you need for high-performance, persistent key-value storage

Memcached Protocol Compatible

Drop-in replacement for Memcached. Use your existing clients and tools—MirDB speaks the standard Memcached text protocol, supporting SET, GET, DELETE, and more.

Persistent Storage

Unlike standard Memcached, your data survives restarts. MirDB persists data to disk using SSTable storage, ensuring durability without sacrificing performance.

LSM Tree Architecture

Built on a 7-level Log-Structured Merge-tree architecture optimized for write-heavy workloads. Automatic compaction keeps performance consistent over time.

Rust Performance

Written in Rust with async networking via Tokio. Memory-safe, fast, and efficient—deploy a single binary with confidence.

Getting Started

Get MirDB up and running in minutes

1 Start the MirDB Server

# Start MirDB server with your configuration file
mirdb -c /path/to/config.toml

2 Connect with Any Memcached Client

# Connect using telnet or any memcached client
telnet localhost 12333

# Store a value
set mykey 0 0 5
hello
STORED

# Retrieve the value
get mykey
VALUE mykey 0 5
hello
END

# Delete a key
delete mykey
DELETED

Configuration

Customize MirDB with a simple TOML configuration file

# Example mirdb.toml configuration

addr = "0.0.0.0:12333"

max_level = 7
work_dir = "/tmp/mirdb"

sst_max_size = "100M"
mem_table_max_size = "4M"

block_size = "4K"
Parameter Description Default
addr Listen address and port 0.0.0.0:12333
max_level Maximum LSM tree levels 7
work_dir Data directory path /tmp/mirdb
sst_max_size Maximum SSTable file size 100M
mem_table_max_size Maximum memtable size before flush 4M
block_size Data block size 4K
