MirDB

Persistent Key-Value Store

A high-performance, disk-based key-value database with full Memcached protocol compatibility. Get the simplicity of Memcached with the durability of persistent storage.

Get Started View on GitHub

Key Features

Memcached Protocol Compatible

Drop-in replacement for Memcached with full protocol compatibility. Use your existing Memcached clients and libraries without any code changes.

Persistent Storage

Unlike in-memory caches, MirDB persists all data to disk. Your data survives server restarts and system failures.

LSM Tree Architecture

Built on a Log-Structured Merge (LSM) tree architecture optimized for write-heavy workloads with efficient compaction.

Skip List Memtable

In-memory writes use a high-performance Skip list data structure for fast insertions and lookups before flushing to disk.

ACID Durability via WAL

Write-Ahead Logging (WAL) ensures ACID durability. Every write is logged before acknowledgment, guaranteeing data integrity.

Efficient Block Storage

Data is organized in configurable block sizes for optimal I/O performance, with support for compression and caching.

Quick Start

Get started with MirDB in seconds using the Memcached protocol.

Start the server 
# Start the server
mirdb-server
Set a value (Memcached protocol) 
set mykey 0 0 5
hello
STORED
Get a value 
get mykey
VALUE mykey 0 5
hello
END

Default Configuration

MirDB comes with sensible defaults that work out of the box. Here are the key configuration settings:

Setting Default Value Description
Listen Address 0.0.0.0:12333 Server binding address and port
Work Directory /tmp/mirdb Data storage location
Max LSM Levels 7 Maximum depth of the LSM tree
SSTable Max Size 100 MB Compaction threshold for SSTables
Memtable Max Size 4 MB Threshold to flush memtable to disk
Block Size 4 KB I/O read and write unit size
