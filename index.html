Why MirDB?

Three key differentiators that make MirDB the right choice for your data storage needs

🔌

Memcached Compatible

Full support for the standard memcached text protocol. Use your existing memcached client libraries seamlessly. Supports SET, GET, ADD, REPLACE, APPEND, PREPEND, DELETE and more commands out of the box.

💾

Data Persistence

Unlike standard memcached, your data survives restarts. MirDB uses a Write-Ahead Log (WAL) for durability and SSTable-based storage for efficient disk usage. Never lose your cached data again.

⚡

High Performance

Built on LSM tree architecture for exceptional write throughput. Features efficient compaction strategies, configurable memory and disk parameters, and optimized data structures for blazing fast operations.

Supported Commands

MirDB implements the memcached text protocol with support for all essential commands

SET

Store a key-value pair in the database. Overwrites existing values if the key already exists.

GET

Retrieve the value associated with one or more keys from the database.

ADD

Store a key-value pair only if the key does not already exist in the database.

REPLACE

Update an existing key-value pair. Fails if the key does not exist.

APPEND

Append data to the end of an existing value without modifying its flags or expiration time.

PREPEND

Prepend data to the beginning of an existing value without modifying its flags or expiration time.

DELETE

Remove a key and its associated value from the database permanently.

Quick Start

Get up and running with MirDB in minutes

Installation

# Build from source cargo build --release

Running MirDB

./mirdb -c /path/to/config.toml

Basic Operations

# Connect with telnet telnet localhost 12333 # Set a value set mykey 0 0 5 hello STORED # Get a value get mykey VALUE mykey 0 5 hello END # Delete a value delete mykey DELETED

Configuration

Customize MirDB for your workload with TOML configuration

Default Configuration

# Network settings addr = "0.0.0.0:12333" # Storage settings max_level = 7 work_dir = "/tmp/mirdb" # SSTable settings sst_max_size = "100M" block_size = "4K" # Memory table settings mem_table_max_size = "4M" # Compaction settings l0_compaction_trigger = 4

Configuration Parameters

addr Listen address and port (default: 0.0.0.0:12333)
work_dir Data directory path (default: /tmp/mirdb)
mem_table_max_size Maximum memtable size before flush (default: 4M)
sst_max_size Maximum SSTable file size (default: 100M)
l0_compaction_trigger Level 0 files before compaction triggers (default: 4)
