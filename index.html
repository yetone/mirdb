Key Features

Memcached Protocol

Drop-in compatibility with existing Memcached clients. Use your favorite tools and libraries.

LSM-Tree Architecture

Optimized for write-heavy workloads with efficient reads using Log-Structured Merge-tree.

Write-Ahead Logging

Data durability with crash recovery. Your data is safe even during unexpected shutdowns.

Skip List Memtable

Fast in-memory operations with O(log n) complexity for inserts and lookups.

Snappy Compression

Reduced storage footprint with fast Snappy compression for data blocks.

Cuckoo Filter

Efficient key existence checks without disk reads for improved query performance.

Architecture Overview

MirDB uses a Log-Structured Merge-tree (LSM-tree) architecture optimized for write-heavy workloads with efficient reads.

How It Works

The LSM-tree architecture provides excellent write performance by converting random writes into sequential I/O:

  • Write Path: Data is first written to the Write-Ahead Log (WAL) for durability, then inserted into the in-memory Memtable (implemented as a skip list for O(log n) operations).
  • Memtable Flush: When the memtable reaches its size limit, it becomes immutable and is flushed to disk as a sorted SSTable file at Level 0.
  • Compaction: Background compaction merges SSTables across levels, removing duplicates and maintaining sorted order for efficient reads.
  • Read Path: Reads check the memtable first (newest data), then search through SSTable levels. Cuckoo filters enable fast key existence checks without disk reads.

Quick Start

Get MirDB up and running in minutes with these simple steps.

Installation

Clone the repository and build with Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release

Configuration

Create a configuration file at etc/mirdb.toml:

# etc/mirdb.toml
addr = "0.0.0.0:12333"

max_level = 7
work_dir = "/tmp/mirdb"

sst_max_size = "100M"
mem_table_max_size = "4M"
mem_table_max_height = 32

imm_mem_table_max_count = 16

block_size = "4K"
block_restart_interval = 16

l0_compaction_trigger = 4

thread_sleep_ms = 500

Running the Server

Start MirDB with your configuration:

# Run with configuration file
cargo run --release -- -c etc/mirdb.toml

Basic Usage

Connect using telnet or any Memcached client:

# Connect to MirDB
telnet localhost 12333

# Set a value (format: set <key> <flags> <exptime> <bytes>)
set mykey 0 0 5
hello
STORED

# Get the value
get mykey
VALUE mykey 0 5
hello
END

Supported Commands

MirDB supports the following Memcached protocol commands:

Getter Commands

Command Description
get Retrieve a value by key
gets Retrieve a value with CAS token

Setter Commands

Command Description
set Store a key-value pair
add Store only if key doesn't exist
replace Store only if key exists
append Append data to existing value
prepend Prepend data to existing value

Other Commands

Command Description
delete Remove a key-value pair
