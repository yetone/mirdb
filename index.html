MirDB

Persistent Key-Value Store with Memcached Protocol

A high-performance, persistent key-value store written in Rust. Drop-in replacement for Memcached with durable storage powered by LSM tree architecture.

View on GitHub Documentation

Key Features

Memcached Protocol Compatibility

Full compatibility with the Memcached text protocol. Use your existing Memcached clients without any code changes. Supports GET, SET, ADD, REPLACE, DELETE, and more.

Persistent Storage with SSTables

Unlike in-memory caches, MirDB persists your data to disk using SSTables (Sorted String Tables). Your data survives restarts and system failures with Write-Ahead Logging (WAL).

LSM Tree Architecture

Built on Log-Structured Merge-tree (LSM) architecture for optimal write performance. Data flows from WAL to Memtable to immutable SSTables with automatic minor and major compaction.

Async Networking with Tokio

High-performance asynchronous networking powered by Tokio runtime. Handle thousands of concurrent connections efficiently with Rust's zero-cost abstractions and memory safety.

Architecture

WAL (Write-Ahead Log)

Every write is first appended to the Write-Ahead Log for durability. This ensures data survives crashes and enables recovery. The WAL provides sequential write performance.

Memtable

The active in-memory data structure (implemented as a skip list) where writes are stored. Provides fast reads and writes. When full, it becomes immutable and a new memtable is created.

Immutable Memtables

A queue of memtables waiting to be flushed to disk. Minor compaction converts these to Level 0 SSTables. This allows writes to continue while flushing happens in the background.

SSTables (Sorted String Tables)

Persistent, sorted key-value files on disk organized in levels. Level 0 may have overlapping keys, while higher levels are sorted and non-overlapping. Major compaction merges and sorts data between levels.

Default Configuration

MirDB uses sensible defaults that work for most use cases. Here are the default configuration parameters for reference:

Parameter Default Value Description
addr 0.0.0.0:12333 Server listen address and port
max_level 7 Maximum LSM tree levels
work_dir /tmp/mirdb Data directory path
sst_max_size 100M Maximum SSTable file size
mem_table_max_size 4M Maximum memtable size before flush
block_size 4K Data block size

To customize these values, create a TOML configuration file and pass it with --config flag.

Quick Start

1. Installation

Clone the repository and build from source:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release

# Run the server
./target/release/mirdb-server

2. Configuration

Create a configuration file (optional - defaults are sensible):

# Server address
addr = "0.0.0.0:12333"

# LSM tree configuration
max_level = 7
work_dir = "/tmp/mirdb"

# Storage sizes
sst_max_size = "100M"
mem_table_max_size = "4M"
block_size = "4K"

Start the server with a custom configuration:

./target/release/mirdb-server --config mirdb.toml

3. Usage

Connect using any Memcached client. Here's an example using Python:

from pymemcache.client import base

# Connect to MirDB
client = base.Client(('localhost', 12333))

# Store a value
client.set('mykey', 'Hello, MirDB!')

# Retrieve the value
result = client.get('mykey')
print(result)  # Output: b'Hello, MirDB!'

# Delete the key
client.delete('mykey')

Or use telnet for quick testing:

# Connect via telnet
telnet localhost 12333

# Set a value (format: set <key> <flags> <exptime> <bytes>)
set greeting 0 0 5
hello
STORED

# Get the value
get greeting
VALUE greeting 0 5
hello
END

4. Supported Commands

MirDB supports the following Memcached commands:

// Storage Commands
SET, ADD, REPLACE, APPEND, PREPEND

// Retrieval Commands
GET, GETS

// Deletion Commands
DELETE

// MirDB-Specific Commands
INFO           // Get server information
MAJOR_COMPACTION  // Trigger manual compaction
