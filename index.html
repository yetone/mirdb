MirDB

A persistent key-value store with Memcached protocol support

Built in Rust with LSM tree architecture for efficient storage. Drop-in replacement for Memcached with data persistence using SSTables.

Get Started View on GitHub

Key Features

Memcached Protocol

Compatible with the standard Memcached text protocol. Existing clients work seamlessly.

Persistent Storage

Unlike Memcached, MirDB persists data to disk using SSTables (Sorted String Tables).

LSM Tree Architecture

Log-Structured Merge-tree with memtables, immutable memtables, and multi-level compaction.

Async Rust + Tokio

Built with async Rust and Tokio for high-performance concurrent networking.

Getting Started

Installation

Option 1: Install via Cargo

cargo install mirdb

Option 2: Build from Source

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build the project
cargo build --release

Starting the Server

# Run with default configuration
./target/release/mirdb-server

# Or run with custom config file
./target/release/mirdb-server -c etc/mirdb.toml

The server will start listening on 0.0.0.0:12333 by default.

Supported Memcached Commands

MirDB implements the memcached text protocol with the following commands:

Storage Commands

  • SET - Store a key-value pair
  • ADD - Store only if key doesn't exist
  • REPLACE - Store only if key exists
  • APPEND - Append data to existing value
  • PREPEND - Prepend data to existing value

Retrieval Commands

  • GET - Retrieve one or more keys
  • GETS - Retrieve with CAS token

Deletion Commands

  • DELETE - Remove a key from the database

MirDB-Specific Commands

  • INFO - Display database status and level information
  • MAJOR_COMPACTION - Trigger manual compaction

Configuration

MirDB uses TOML configuration files. Customize settings to tune performance for your workload.

Example Configuration

# MirDB Configuration File
addr = "0.0.0.0:12333"

max_level = 7
work_dir = "/tmp/mirdb"

sst_max_size = "100M"
mem_table_max_size = "4M"
mem_table_max_height = 32

imm_mem_table_max_count = 16

block_size = "4K"
block_restart_interval = 16

l0_compaction_trigger = 4

thread_sleep_ms = 500

Configuration Parameters

Parameter Description Default
addr Listen address and port 0.0.0.0:12333
max_level Maximum LSM tree levels 7
work_dir Data directory path /tmp/mirdb
sst_max_size Maximum SSTable file size 100MB
mem_table_max_size Max memtable size before flush 4MB
block_size Data block size 4KB

For more advanced configuration options and detailed documentation, see the configuration documentation.
