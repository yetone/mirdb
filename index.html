MirDB

Persistent Key-Value Store with Memcached Protocol

Get Started View on GitHub

Why MirDB?

Drop-in Memcached Compatibility

Use your existing memcached clients without any code changes. MirDB implements the standard memcached text protocol, making migration seamless and effortless.

Built-in Persistence

Unlike standard memcached, your data survives restarts. MirDB persists data to disk using SSTable-based storage with write-ahead logging for durability.

LSM Tree Architecture

Optimized for write-heavy workloads with a Log-Structured Merge-tree architecture. Automatic compaction keeps your storage efficient and queries fast.

Supported Commands

MirDB implements the memcached text protocol with additional administrative commands.

Storage Commands

  • SET - Store a key-value pair
  • ADD - Store only if key doesn't exist
  • REPLACE - Store only if key exists
  • APPEND - Append data to existing value
  • PREPEND - Prepend data to existing value

Retrieval Commands

  • GET - Retrieve one or more keys
  • GETS - Retrieve with CAS token

Deletion Commands

  • DELETE - Remove a key

MirDB-Specific Commands

  • INFO - Display database status and level information
  • MAJOR_COMPACTION - Trigger manual compaction

MirDB vs Standard Memcached

See how MirDB compares to standard memcached and what makes it different.

Getting Started

1 Installation

Clone the repository and build MirDB using Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build the project
cargo build --release

# Run MirDB with the default configuration
./target/release/mirdb-server -c etc/mirdb.toml

2 Configuration

MirDB uses TOML configuration files. Here's an example configuration (etc/mirdb.toml):

addr = "0.0.0.0:12333"

max_level = 7
work_dir = "/tmp/mirdb"

sst_max_size = "100M"
mem_table_max_size = "4M"
mem_table_max_height = 32

imm_mem_table_max_count = 16

block_size = "4K"
block_restart_interval = 16

l0_compaction_trigger = 4

thread_sleep_ms = 500

3 Basic Usage

Connect using any memcached client or tools like telnet or nc:

# Connect to MirDB
telnet localhost 12333

# Or using netcat
nc localhost 12333

# Store a value
set mykey 0 0 5
hello
STORED

# Retrieve the value
get mykey
VALUE mykey 0 5
hello
END

# Delete a key
delete mykey
DELETED

4 Supported Commands

MirDB supports the following memcached commands:

  • Storage: SET, ADD, REPLACE, APPEND, PREPEND
  • Retrieval: GET, GETS
  • Deletion: DELETE
  • MirDB-specific: INFO, MAJOR_COMPACTION

Client Connection Examples

Connect to MirDB using any memcached-compatible client. Here are examples in popular languages.

Python

Using pymemcache library:

from pymemcache.client import Client

# Connect to MirDB
client = Client(('localhost', 12333))

# Store a value
client.set('user:1', 'John Doe')

# Retrieve the value
result = client.get('user:1')
print(result)  # b'John Doe'

# Delete a key
client.delete('user:1')

Node.js

Using memcached library:

const Memcached = require('memcached');

// Connect to MirDB
const client = new Memcached('localhost:12333');

// Store a value
client.set('session:abc', 'user_data', 3600, (err) => {
  if (err) console.error(err);
});

// Retrieve the value
client.get('session:abc', (err, data) => {
  console.log(data);  // 'user_data'
});

// Delete a key
client.del('session:abc', (err) => {
  if (err) console.error(err);
});

Ruby

Using dalli gem:

require 'dalli'

# Connect to MirDB
client = Dalli::Client.new('localhost:12333')

# Store a value
client.set('cache:key', 'cached_value')

# Retrieve the value
result = client.get('cache:key')
puts result  # 'cached_value'

# Delete a key
client.delete('cache:key')

Architecture Overview

MirDB uses a Log-Structured Merge-tree (LSM tree) architecture optimized for write-heavy workloads with automatic background compaction.

Key Components

  • WAL (Write-Ahead Log): Ensures durability by logging all writes before they're applied to memory.
  • Memtable: An in-memory skip list that stores recent writes for fast access.
  • Immutable Memtables: Frozen memtables queued for flushing to disk.
  • SSTables: Sorted String Tables stored on disk, organized into levels for efficient retrieval.

Compaction Process

  • Minor Compaction: Flushes immutable memtables to Level 0 SSTables.
  • Major Compaction: Merges SSTables between levels to maintain sorted order and reclaim space.
