MirDB

A Persistent Key-Value Store with Memcached Protocol

Fast, reliable, and built with Rust. MirDB combines the simplicity of memcached with the durability of persistent storage using LSM tree architecture.

Get Started View on GitHub

Key Features

Memcached Protocol

Compatible with the standard memcached text protocol. Use existing memcached clients without modification.

Data Persistence

Unlike memcached, MirDB persists data to disk using SSTables, surviving restarts and failures.

LSM Tree Architecture

Efficient write performance with background compaction and multi-level storage optimization.

Built with Rust

Tokio-based async networking with memory safety guarantees and high performance.

Quick Start

Get up and running with MirDB in minutes.

1. Installation

Clone the repository and build with Cargo:

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build and run with Cargo
cargo run --release

2. Connect with Any Memcached Client

MirDB works with any memcached-compatible client. Here's an example using Python:

import memcache

# Connect to MirDB (default port: 12333)
client = memcache.Client(['localhost:12333'])

# Store data with SET
client.set('user:1', 'John Doe')
client.set('counter', '42')

# Retrieve data with GET
name = client.get('user:1')
print(f"User: {name}")  # Output: User: John Doe

count = client.get('counter')
print(f"Counter: {count}")  # Output: Counter: 42

# Delete data
client.delete('counter')

3. Using the Raw Protocol

You can also connect directly using telnet or netcat:

# Connect to MirDB
telnet localhost 12333

# SET a key-value pair
set mykey 0 0 5
hello
STORED

# GET the value back
get mykey
VALUE mykey 0 5
hello
END

4. Configuration

Default configuration values:

# MirDB default configuration
listen_address = "0.0.0.0:12333"
work_directory = "/tmp/mirdb"
max_lsm_levels = 7
sstable_max_size = "100MB"
memtable_max_size = "4MB"
block_size = "4KB"

Supported Commands

Storage

  • SET - Store a key-value pair
  • ADD - Store only if key doesn't exist
  • REPLACE - Store only if key exists
  • APPEND - Append to existing value
  • PREPEND - Prepend to existing value

Retrieval

  • GET - Retrieve one or more keys
  • GETS - Retrieve with CAS token

Deletion

  • DELETE - Remove a key

Administration

  • INFO - Database status
  • MAJOR_COMPACTION - Trigger compaction

Technical Specifications

Configuration defaults and system requirements for running MirDB.

Configuration Defaults

Parameter Default Value
Listen Address 0.0.0.0:12333
Work Directory /tmp/mirdb
Max LSM Levels 7
SSTable Max Size 100MB
Memtable Max Size 4MB
Block Size 4KB
L0 Compaction Trigger 4 files

System Requirements

  • Rust Rust 2018 edition or later with Cargo build system
  • Tokio Runtime Async runtime for non-blocking I/O operations
  • Operating System Linux, macOS, or Windows with POSIX-compatible filesystem
  • Memory Minimum 512MB RAM (recommended 2GB+ for production)
  • Disk Space Depends on data volume; SSTable storage uses ~2x data size during compaction
