MirDB

A persistent key-value store with memcached protocol compatibility

Built with Rust for performance and reliability. Drop-in replacement for memcached with data persistence using LSM tree architecture.

Get Started View on GitHub

Persistent Storage

Unlike memcached, MirDB persists your data to disk using LSM tree architecture with SSTables. Your data survives restarts and crashes.

Memcached Compatible

Drop-in replacement using the standard memcached text protocol. Your existing memcached clients connect seamlessly without any code changes.

Written in Rust

Built with Rust for memory safety, performance, and reliability. Async I/O powered by Tokio for handling thousands of concurrent connections.

Key Features

LSM Tree Architecture

MirDB uses a Log-Structured Merge-tree approach with memtables, immutable memtables, and multi-level SSTable compaction for efficient write performance and reliable storage.

Async I/O with Tokio

Built on Tokio for high-performance asynchronous networking. Handle thousands of concurrent connections efficiently with Rust's async/await runtime.

Configurable Parameters

Fine-tune MirDB for your workload with TOML configuration. Adjust memtable size, SSTable limits, compaction triggers, and more to optimize performance.

Background Compaction

Automatic background compaction keeps your data organized. Minor compaction flushes memtables to disk, while major compaction merges SSTables across levels.

Quick Start

Installation

Install MirDB using Cargo (Rust's package manager):

# Install from crates.io (recommended)
cargo install mirdb

Or Build from Source

# Clone and build from source
git clone https://github.com/yetone/mirdb
cd mirdb
cargo build --release

Run MirDB

# Run MirDB server
./target/release/mirdb

Connect and Test

Connect with any memcached-compatible client:

# Connect with telnet
telnet localhost 12333

Basic Usage

Try SET and GET commands:

# Set a key-value pair
set hello 0 0 5
world
STORED

# Get the value back
get hello
VALUE hello 0 5
world
END

Supported Commands

Storage Commands

SET

Store a key-value pair. Overwrites existing value if key exists.

set <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n

# Example:
set mykey 0 3600 5
hello
STORED

ADD

Store a key-value pair only if the key does not already exist.

add <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n

# Example:
add newkey 0 0 5
world
STORED

REPLACE

Store a key-value pair only if the key already exists.

replace <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n

# Example:
replace mykey 0 0 6
world!
STORED

APPEND

Append data to an existing key's value.

append <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n

# Example:
append mykey 0 0 6
_extra
STORED

PREPEND

Prepend data to an existing key's value.

prepend <key> <flags> <ttl> <bytes> [noreply]\r\n
<data>\r\n

# Example:
prepend mykey 0 0 7
prefix_
STORED

Retrieval Commands

GET

Retrieve the value for one or more keys.

get <key1> [<key2> ...]\r\n

# Example:
get mykey
VALUE mykey 0 5
hello
END

# Multiple keys:
get key1 key2 key3
VALUE key1 0 5
value1
VALUE key2 0 5
value2
END

GETS

Retrieve value with CAS (Check-And-Set) token for optimistic locking.

gets <key1> [<key2> ...]\r\n

# Example:
gets mykey
VALUE mykey 0 5 12345
hello
END

Deletion Commands

DELETE

Remove a key from the database.

delete <key> [noreply]\r\n

# Example:
delete mykey
DELETED

# Key not found:
delete nonexistent
NOT_FOUND

MirDB-Specific Commands

INFO

Display database status and LSM tree level information.

info\r\n

# Example:
info
MirDB Status:
  Memtable entries: 1234
  SSTable levels: 7
  Total keys: 50000
END

MAJOR_COMPACTION

Trigger a manual major compaction to merge SSTables and reclaim space.

major_compaction\r\n

# Example:
major_compaction
OK

Configuration

MirDB uses TOML configuration files. Configure MirDB by creating a configuration file and passing it via the -c flag:

mirdb -c /path/to/config.toml

Configuration Parameters

addr Listen address and port for the server 0.0.0.0:12333
max_level Maximum number of LSM tree levels 7
work_dir Data directory path for storing SSTable files /tmp/mirdb
sst_max_size Maximum SSTable file size before splitting 100M
mem_table_max_size Maximum memtable size before flush to disk 4M
block_size Data block size within SSTable files 4K

Example Configuration

# MirDB Configuration (TOML format)
addr = "0.0.0.0:12333"
max_level = 7
work_dir = "/tmp/mirdb"
sst_max_size = "100M"
mem_table_max_size = "4M"
block_size = "4K"
