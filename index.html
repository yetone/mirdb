MirDB

Persistent Key-Value Store with Memcached Protocol

MirDB brings persistence to memcached. Get the familiar protocol you know with the durability your data deserves.

Get Started View on GitHub

Key Features

🔌

Memcached Compatible

Use your existing clients and tooling. MirDB implements the standard memcached text protocol, allowing seamless integration with any memcached client library.

💾

Persistent Storage

Your data survives restarts. Unlike traditional memcached, MirDB persists data to disk using SSTable storage, ensuring durability without sacrificing performance.

⚡

High Performance

Built on LSM tree architecture with efficient compaction. Async networking via Tokio and skip list-based memtables deliver the speed you need.

Supported Commands

MirDB implements the memcached text protocol, enabling compatibility with existing memcached clients.

Storage Commands

  • SET - Store a key-value pair
  • ADD - Store only if key doesn't exist
  • REPLACE - Store only if key exists
  • APPEND - Append data to existing value
  • PREPEND - Prepend data to existing value

Retrieval Commands

  • GET - Retrieve one or more keys
  • GETS - Retrieve with CAS token

Deletion Commands

  • DELETE - Remove a key

MirDB Extensions

  • INFO - Display database status and level information
  • MAJOR_COMPACTION - Trigger manual compaction

Quick Start

1. Installation

# Install from source using Cargo
cargo install mirdb-server

# Or clone and build manually
git clone https://github.com/yetone/mirdb.git
cd mirdb
cargo build --release

2. Configuration

# mirdb.toml
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"
mem_table_max_size = "4M"
sst_max_size = "100M"

3. Connect & Use

# Connect with any memcached client
telnet localhost 12333

# Store a value
set mykey 0 0 5
hello
STORED

# Retrieve a value
get mykey
VALUE mykey 0 5
hello
END

Configuration

MirDB uses TOML configuration files for customization. Create a configuration file and pass it using the -c flag, or modify the defaults to suit your deployment needs.

Default Configuration

# mirdb.toml - Default configuration options
addr = "0.0.0.0:12333"
work_dir = "/var/lib/mirdb"
mem_table_max_size = "4M"
sst_max_size = "100M"

Configuration Options

addr
Listen address and port. Default: 0.0.0.0:12333
work_dir
Data directory path for storing SSTable files and WAL. Example: /var/lib/mirdb
mem_table_max_size
Maximum memtable size before flushing to disk. Default: 4M (4 megabytes)
sst_max_size
Maximum SSTable file size. Default: 100M (100 megabytes)

Customization Tips

  • Increase mem_table_max_size for write-heavy workloads to reduce flush frequency
  • Set work_dir to a path on fast storage (SSD) for optimal performance
  • Use size suffixes: K (kilobytes), M (megabytes), G (gigabytes)
  • Run with: mirdb -c /path/to/mirdb.toml
