Architecture Overview

MirDB uses an LSM (Log-Structured Merge) tree architecture for efficient writes and durable storage. Data flows through multiple stages to ensure both performance and persistence.

How Data Flows Through MirDB

  1. WAL (Write-Ahead Log): Every write is first recorded in the WAL for crash recovery and durability. This ensures no data is lost even if the server crashes.
  2. Memtable: Data is then inserted into an in-memory skip list structure for fast writes and lookups. The memtable provides O(log n) operations.
  3. SSTable Flush: When the memtable reaches capacity (default 4MB), it is flushed to disk as an immutable SSTable at Level 0.
  4. Compaction: Background threads merge and compact SSTables across levels, optimizing read performance and reclaiming space from deleted keys.
