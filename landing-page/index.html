MirDB

A Persistent Key-Value Store with Memcached Protocol

A high-performance, drop-in memcached replacement with persistence guarantees. Use your existing memcached clients without modification while gaining durable storage powered by LSM-tree architecture.

Get Started View on GitHub

Key Features

Memcached Compatible

Existing memcached clients work without modification. Drop-in replacement with full protocol support for get, set, delete, and more commands.

Persistent Storage

Data survives restarts with LSM-tree architecture and SSTable-based storage. Write-ahead logging ensures durability without sacrificing performance.

High Performance

Optimized for speed with skip-list memtable implementation and intelligent compaction strategies for consistent read and write performance.

Configurable

Flexible configuration options for various deployment scenarios. Tune memtable size, compaction triggers, and storage parameters to match your workload.

Write-Ahead Log (WAL)

The WAL provides durability by persisting every write to disk before acknowledging it. Each WAL segment corresponds to one memtable, with keys and values Snappy-compressed for efficiency.

  • Writes are logged before updating the memtable
  • Crash recovery rebuilds memtables from WAL segments
  • Segments are deleted after successful compaction

Memtable (Skip List)

The memtable is an in-memory skip list data structure optimized for concurrent reads and writes. It provides O(log n) insertion and lookup performance.

  • Default maximum size: 4MB (mem_table_max_size)
  • Maximum height: 32 levels (mem_table_max_height)
  • Becomes immutable when full, replaced by new empty memtable

SSTables (Sorted String Tables)

SSTables are immutable, sorted files on disk containing key-value pairs organized into blocks. They form the persistent storage layer of the LSM-tree.

  • Block-based format with configurable block size (default 4KB)
  • Bloom filters for efficient negative lookups
  • Index blocks enable binary search within files

Compaction

Compaction merges SSTables to reclaim space and maintain read performance. MirDB supports both minor and major compaction processes.

  • Minor compaction: Flushes immutable memtables to Level 0
  • Major compaction: Merges Level N SSTables into Level N+1
  • Triggered when Level 0 reaches 4 files (l0_compaction_trigger)
  • Each level is ~10x larger than the previous

Configuration

MirDB uses TOML configuration files for flexible deployment. Customize storage, memory, and compaction settings to match your workload.

mirdb.toml 
# Network configuration
addr = "0.0.0.0:12333"

# Storage configuration
max_level = 7
work_dir = "/tmp/mirdb"

# SSTable configuration
sst_max_size = "100M"

# Memory table configuration
mem_table_max_size = "4M"
mem_table_max_height = 32
imm_mem_table_max_count = 16

# Block configuration
block_size = "4K"
block_restart_interval = 16

# Compaction settings
l0_compaction_trigger = 4
thread_sleep_ms = 500

Configuration Parameters

Parameter Description Default
addr Server listen address and port for memcached protocol connections 0.0.0.0:12333
work_dir Directory path for storing SSTable files and write-ahead logs /tmp/mirdb
max_level Maximum number of levels in the LSM tree hierarchy 7
mem_table_max_size Maximum size of memtable before flushing to disk (supports K, M, G suffixes) 4M
mem_table_max_height Maximum height of the skip list used in the memtable 32
sst_max_size Maximum size of individual SSTable files (supports K, M, G suffixes) 100M
block_size Size of data blocks within SSTables (supports K, M, G suffixes) 4K
l0_compaction_trigger Number of Level 0 files that triggers major compaction 4
imm_mem_table_max_count Maximum number of immutable memtables queued for flushing 16
block_restart_interval Key prefix restart interval for delta encoding in blocks 16
thread_sleep_ms Background thread sleep interval in milliseconds 500

Getting Started

Get MirDB up and running in minutes. Choose the installation method that works best for you.

Option 1: Build from Source

Clone the repository and build MirDB using Cargo:

  1. Clone the repository: 
    git clone https://github.com/yetone/mirdb.git
cd mirdb
  2. Build the project: 
    cargo build --release
  3. Run MirDB: 
    ./target/release/mirdb

Option 2: Install via Cargo

Install MirDB directly using Cargo (requires Rust toolchain):

  1. Install with cargo: 
    cargo install mirdb
  2. Run MirDB: 
    mirdb

Quick Start

Once MirDB is running, you can connect using any memcached client. Here's a quick test using netcat:

# Connect to MirDB (default port: 12333)
nc localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get the value
get mykey
VALUE mykey 0 5
hello
END
