Frequently Asked Questions

MirDB is a blazing-fast, persistent key-value store that combines the speed of in-memory databases like Memcached with the durability of disk-based storage. Unlike Redis, MirDB uses a skiplist-based memtable architecture for consistent sub-millisecond performance, and unlike Memcached, it persists your data across restarts using SSTable-based storage with automatic compaction.

Yes! MirDB implements the full Memcached protocol, which means you can use any existing Memcached client library in your preferred programming language. Simply point your client to MirDB instead of Memcached, and you'll get persistence and improved performance without changing a single line of application code.

Getting started is easy! Clone the repository from GitHub, build the project using Cargo (Rust's package manager), and run the server. MirDB will start listening on the default Memcached port. Check our documentation for detailed installation instructions, configuration options, and best practices for production deployments.

MirDB is designed with production workloads in mind. It features automatic data compaction, crash recovery, and efficient memory management. However, as with any database, we recommend thorough testing with your specific workload and data patterns before deploying to production. Join our community to learn from others who are using MirDB in production environments.
