MirDB

Persistent Key-Value Store with Memcached Protocol Compatibility

A high-performance, Rust-powered database with LSM-tree architecture. Drop-in replacement for Memcached with data persistence.

Get Started View on GitHub

Why MirDB?

Persistent Storage

Your data survives restarts. Unlike in-memory caches, MirDB persists data to disk ensuring durability.

Memcached Protocol

Drop-in replacement with no code changes. Use your existing Memcached clients seamlessly.

LSM-Tree Architecture

Optimized for write-heavy workloads with Log-Structured Merge-Tree design for high throughput.

Minor/Major Compaction

Automatic storage optimization through intelligent minor and major compaction processes.

Rust-Powered

Memory safety and performance without compromise. Built with Rust for reliability and speed.

Async I/O

Built on Tokio for scalability. Handle thousands of concurrent connections efficiently.

Simple as Memcached

Use familiar Memcached commands with your existing clients. MirDB speaks the same protocol.

Start the Server 
# Start MirDB server on default port
mirdb --port 11211 --data-dir ./data
Basic SET/GET Operations 
# Connect using telnet or any Memcached client
telnet localhost 11211

# SET a key-value pair (key, flags, exptime, bytes)
SET mykey 0 0 5
hello
STORED

# GET the value back
GET mykey
VALUE mykey 0 5
hello
END

How It Works

MirDB uses a Log-Structured Merge-Tree (LSM-tree) architecture, optimized for write-heavy workloads with efficient reads.

flowchart TB subgraph WritePathSection["Write Path"] direction TB Client1["Client"] --> Memtable["Memtable (In-Memory)"] Memtable --> WAL["WAL (Write-Ahead Log)"] WAL --> SSTable1["SSTable (Level 0)"] end subgraph ReadPathSection["Read Path"] direction TB Client2["Client"] --> MemtableRead["Memtable"] MemtableRead --> SSTablesRead["SSTables (L0 → Ln)"] end subgraph CompactionSection["Compaction Process"] direction TB SSTableL0["Level 0 SSTables"] --> MinorCompaction["Minor Compaction"] MinorCompaction --> SSTableL1["Level 1 SSTables"] SSTableL1 --> MajorCompaction["Major Compaction"] MajorCompaction --> SSTableLn["Level N SSTables"] end

Core Components

Memtable

An in-memory data structure (skip list) that holds recent writes. Provides fast reads and writes before data is flushed to disk.

SSTables

Sorted String Tables are immutable, on-disk files containing sorted key-value pairs. Organized in levels for efficient read operations.

Write-Ahead Log (WAL)

A durable log that records all writes before they're applied. Ensures data recovery after crashes without data loss.

Compaction

Background process that merges and sorts SSTables across levels. Minor compaction merges L0 files; major compaction optimizes deeper levels.

Get Started in Minutes

Install MirDB and start using it with your existing Memcached clients in just a few steps.

1

Install MirDB

Install MirDB using Cargo, Rust's package manager. Make sure you have Rust installed first.

Installation 
cargo install mirdb
2

Configure (Optional)

Create a configuration file to customize MirDB settings. Save this as mirdb.toml:

mirdb.toml 
# MirDB Configuration
[server]
port = 11211
host = "127.0.0.1"

[storage]
data_dir = "./data"
wal_enabled = true

[memtable]
max_size = 67108864  # 64MB
3

Start the Server

Run MirDB with your configuration. It will start listening for Memcached protocol connections.

Start Server 
# Start with default settings
mirdb

# Or with custom config
mirdb --config mirdb.toml
