MirDB

Persistent Key-Value Storage with Memcached Compatibility

A high-performance, persistent key-value store that speaks the memcached protocol. Drop-in replacement for memcached with data durability powered by LSM-tree architecture.

Get Started View on GitHub

Key Features

Memcached Protocol Compatible

Drop-in replacement for existing memcached clients. No code changes required to switch from standard memcached.

Persistent Storage

Data survives restarts using SSTables. Never lose your cached data again with durable on-disk storage.

High Performance

LSM-tree architecture with async I/O via Tokio delivers excellent write throughput and read performance.

Configurable

Extensive configuration options for tuning performance, memory usage, and compaction behavior.

LSM-Tree Architecture

┌─────────────────────────────────────┐ │ Client Request │ │ (Memcached Protocol) │ └──────────────┬──────────────────────┘ │ ▼ ┌─────────────────────────────────────┐ │ MirDB Server │ │ ┌─────────┐ ┌──────────────────┐ │ │ │ WAL │ │ Memtable │ │ │ │(Durable)│ │ (In-Memory) │ │ │ └─────────┘ └────────┬─────────┘ │ │ │ │ │ (when full) │ │ ▼ │ │ ┌────────────────────────┐ │ │ │ Immutable Memtables │ │ │ │ (Queue) │ │ │ └───────────┬────────────┘ │ │ │ │ │ (minor compaction) │ │ ▼ │ │ ┌───────────────────────────────┐ │ │ │ SSTable Levels (L0 - L6) │ │ │ │ (Persistent Sorted Storage) │ │ │ └───────────────────────────────┘ │ └─────────────────────────────────────┘

MirDB uses an LSM-tree storage engine with Write-Ahead Log (WAL) for durability, in-memory memtable for fast writes, and tiered SSTable levels for efficient storage.

Get Started

Installation

Build from source using Cargo:

git clone https://github.com/penberg/mirdb.git cd mirdb cargo build --release

Quick Start

Start the server:

./target/release/mirdb-server -c etc/mirdb.toml

Connect with any memcached client:

# Using telnet telnet localhost 12333 # Example commands set mykey 0 0 5 hello STORED get mykey VALUE mykey 0 5 hello END
