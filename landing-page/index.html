MirDB

Persistent Key-Value Store with Memcached Protocol

A drop-in replacement for memcached that persists your data to disk. Built with Rust for memory safety and performance, MirDB combines the simplicity of the memcached protocol with the reliability of persistent storage using LSM tree architecture.

Get Started Learn More

Key Features

Memcached Protocol Compatibility

Compatible with the standard memcached text protocol. Your existing memcached clients work out of the box.

Persistent Storage

Unlike memcached, MirDB persists data to disk using SSTables (Sorted String Tables) for durability.

LSM Tree Architecture

Uses a Log-Structured Merge-tree approach with memtables and multi-level SSTable compaction.

Async Networking (Tokio)

Built on Tokio for high-performance asynchronous I/O and networking.

Write-Ahead Logging

WAL ensures data durability even in case of unexpected shutdowns.

Configurable Compaction

Both minor and major compaction strategies to optimize storage and performance.

Quick Start

Installation

# Clone the repository
git clone https://github.com/yetone/mirdb.git
cd mirdb

# Build with Cargo
cargo build --release

Configuration (config.toml)

[server]
listen_address = "0.0.0.0:12333"
work_directory = "/tmp/mirdb"

[storage]
max_lsm_levels = 7
memtable_max_size = 4194304  # 4MB
sstable_max_size = 104857600 # 100MB
block_size = 4096            # 4KB

Running the Server

# Start MirDB server
./target/release/mirdb-server

Connecting with a Client

# Connect using telnet or any memcached client
telnet localhost 12333

# Set a value
set mykey 0 0 5
hello
STORED

# Get the value
get mykey
VALUE mykey 0 5
hello
END

Supported Commands

Storage Commands

Command Description
SETStore a key-value pair
ADDStore only if key doesn't exist
REPLACEStore only if key exists
APPENDAppend data to existing value
PREPENDPrepend data to existing value

Retrieval Commands

Command Description
GETRetrieve value for one or more keys
GETSRetrieve value with CAS token

Other Commands

Command Description
DELETERemove a key
INFOGet server information (MirDB-specific)
MAJOR_COMPACTIONTrigger major compaction (MirDB-specific)

Configuration

Parameter Default Value Description
addr 0.0.0.0:12333 Server listen address and port
work_dir /tmp/mirdb Directory for data storage
max_level 7 Maximum LSM tree levels
mem_table_max_size 4MB Maximum memtable size before flush
sst_max_size 100MB Maximum SSTable file size
block_size 4KB Block size for SSTable storage

Configuration File Example

# mirdb.toml - Example configuration file
addr = "0.0.0.0:12333"
work_dir = "/tmp/mirdb"

max_level = 7
mem_table_max_size = "4M"
sst_max_size = "100M"
block_size = "4K"

# Optional advanced settings
mem_table_max_height = 32
imm_mem_table_max_count = 16
block_restart_interval = 16
l0_compaction_trigger = 4
thread_sleep_ms = 500
